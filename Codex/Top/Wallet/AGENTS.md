# AGENTS.md - Wallet 模块规则

## 1. 适用范围与信息来源

- 本文件适用于 `E:\Codex\Top\Wallet` 及其子目录；上级 `E:\Codex\Top\AGENTS.md` 继续有效。
- 开始改动前必须先阅读 `核心业务规则.md`；需求细节查阅 `钱包模块-充值与明细PRD.md`，验收和边界查阅 `钱包模块-充值与明细PRD_测试用例.md`。
- 不得修改 PRD 或测试用例来掩盖实现问题。需求、测试与核心规则出现矛盾或缺失时，保留证据并向用户确认，不得自行选择资金口径。

## 2. 业务边界

- 本模块只覆盖金币充值、第三方充值、币商售币及管理、金币/钻石明细、钻石兑换金币。
- 当前版本禁止增加提现、金豆/游戏币能力或金币兑换钻石；金币和钻石是独立账户。
- 兑换金币是否必须为 `6` 的倍数尚未产品确认，是阻塞项。禁止自行增加取整或非整除兑换策略。

## 3. 资产改动硬规则

- 充值、第三方回调、售币和兑换必须由服务端以订单/请求维度保证幂等；重复提交、重复回调只能结算一次。
- 售币的扣币和买方加币、兑换的扣钻和加金币，必须在同一原子事务中完成；不得产生单边余额或单边流水。
- 正式结算前服务端必须重验权限、状态、实时余额、金额和订单状态；客户端预校验只用于交互提示。
- 成功后必须写完整流水、刷新受影响余额和页面数据；异常、中断、回跳失败后的页面状态以服务端最终状态恢复。
- 禁止客户端计算或硬编码第三方最终支付价，必须使用后端返回的价格、手续费、总价和币种。

## 4. 不可变业务参数

| 项目 | 规则 |
|---|---|
| 币商单笔售币 | 正整数，闭区间 `5000` 至 `9000000` |
| 币商可售余额 | `coin + sendCoin`；扣减顺序为 `sendCoin` 后 `coin` |
| 币商充值入口 | 财富等级 `>= 10` |
| 默认币商可见余额 | `>= 1000000` |
| 币商信息长度 | 最多 300 字，允许为空 |
| 新增币商展示国家 | 至少 5 个 |
| 兑换汇率 | `10 Diamonds = 6 Gold coins` |
| 第三方汇率 | 自定义汇率优先；否则渠道汇率乘 `1.003` |
| 第三方金额区间 | 按最终支付总价，包含边界 |
| 第三方金额取整 | 按 `amount_scale` 向上取整 |

## 5. 开发与验证要求

- 所有钱包接口均要求登录；币商和后台管理权限必须由服务端校验，不能只隐藏前端入口。
- 明细必须支持收入与支出，按自然日倒序分组；筛选后从第一页重新分页，重复分页请求不得重复追加数据。
- 一笔兑换成功时，金币收入流水与钻石扣减流水必须使用同一关联标识；余额、订单与流水的交易后余额必须一致。
- 涉及金额、权限、状态机、回调或账变的修改，至少补充/更新覆盖正常、边界、失败、重复请求和中断恢复的测试。
- 文案使用多语言配置；验证中文、英文、阿拉伯语下金额和按钮不遮挡。
- 完成改动后，执行与改动范围匹配的测试，并在交付说明中列出已验证项和未执行项。
