# AGENTS.md — 产品需求文档与测试用例

> 父目录 `..\AGENTS.md` 的通用规范（Python 执行路径、MCP 配置、数据库查询规范、输出风格）同样适用于本子目录。

## 目录用途
产品需求文档（PRD）集中管理，并基于需求文档生成结构化测试用例。

### 命名规范
- 需求文档：`[功能名][版本号].md` 或 `.docx`
- 测试用例：`[需求文档名称]_测试用例.md`，与需求同级

---

## 测试用例生成规则

### 角色定位
专业测试工程师：需求文档 → 结构化、可执行的测试用例

### 输入规则

| 项目 | 规则 |
|:---|:---|
| 扫描范围 | 当前目录下所有需求文档 |
| 支持格式 | `.doc` / `.docx` / `.md` |
| 识别关键词 | `需求` / `spec` / `PRD` / `requirement` 或用户明确指定 |
| 多文档处理 | 逐一处理，分别生成对应用例文件 |
| 读取失败 | 提示检查文件，或建议用户粘贴关键内容 |

> **`.docx` 处理**：Word 文档优先使用可用的 Word/文档处理插件提取文本、表格和文档结构；若文档内图片、截图或扫描内容影响需求识别，应结合文档渲染、OCR、PDF 或视觉处理能力补充识别；仍无法完整识别时，再提示检查文件或请用户粘贴关键内容。

### 输出规则

#### 文件规范
- **保存位置**：当前目录（与需求同级）
- **命名格式**：`[需求文档名称]_测试用例.md`
- **编码**：UTF-8

#### Markdown 层级规范

| 层级 | 格式 | 示例 |
|:---|:---|:---|
| 模块 | `## N.` | `## 1. 薪资模块优化` |
| 子模块 | `### N.M` | `### 1.1 提现限制解除` |
| 场景 | `#### N.M.K` | `#### 1.1.1 提现限制解除` |
| 验证点 | `- 描述` | `- 按钮名称显示正确` |

- 跨模块分隔：`---`
- 子分组：`- **分组名**` + 缩进验证点

#### 输出模板：层次化清单 `- X.Y.Z`

```markdown
# [需求名称] 测试用例

> 生成时间：YYYY-MM-DD
> 需求来源：[文档文件名]
> 格式：层次化清单（`- X.Y.Z 描述`）
> 测试点总数：X 个

## 1. [模块名]
### 1.1 [子模块]
- 1.1.1 可独立验证的检查点描述
- 1.1.2 每个点只检查一个逻辑行为
---
## 2. [下一模块]
```

**格式规则**：
- 每个 `-` 一个可执行、可判断的检查点，禁止合并多个逻辑
- 编号 X.Y.Z 与需求层级对应（模块.子模块.序号）
- 用例行固定使用 `- X.Y.Z 描述`，不使用 `- [ ] X.Y.Z 描述`。
- 保留 `###` 子模块标题辅助导航，但不强制 `####` 场景层级
- 更新 `测试点总数` 后，必须校验实际 `- X.Y.Z` 行数与文件头总数一致。

### 测试设计核心原则

#### 九类必覆盖场景

| 类型 | 验证要点 |
|:---|:---|
| 功能场景 | Tab/状态切换、字段完整性、展示 |
| 规则验证 | 公式、条件分支、计算结果 |
| 边界验证 | 临界值、跨周期、空数据、跨页 |
| 身份/权限 | 不同角色下的字段/功能差异 |
| 多语言 | 中/英/阿拉伯语布局与文案 |
| 计算核验 | 交叉计算、汇总累加、公式代入 |
| 状态流转 | 全量状态节点覆盖、合法/非法跃迁、终态不可逆 |
| 中断与回退 | 取消、关闭、token过期、权限变更、网络中断后的恢复或清理 |
| 操作时序 | 多步骤依赖顺序、前置校验失败不执行后续、并发操作幂等 |

#### 专项补充覆盖规则

生成或补充测试用例时，除主流程外必须按需求适用范围补充以下专项：

| 专项 | 覆盖要求 |
|:---|:---|
| 边界值 | 覆盖 `0`、等于阈值、超过阈值、负数、小数精度、空数据 |
| 端到端链路 | 覆盖申请 → 审核 → 客户端记录 → 结算/状态变化 → 历史快照 → 后台导出 |
| 状态与幂等 | 覆盖重复点击、并发审核、通过后再拒绝、拒绝后再通过、刷新后状态保持 |
| 权限绕过 | 同时覆盖按钮可见性、直接 URL、直接接口调用 |
| 导出一致性 | 覆盖字段包含、字段顺序、筛选范围、金额精度、空数据导出、乱码 |
| 多身份变化 | 覆盖同一用户多身份、角色升降级、历史债务和历史快照不被当前身份覆盖 |
| 多语言 | 覆盖中/英/阿字段完整性，阿语布局不遮挡、不错列 |
| 待确认项 | P0/P1 待确认项标记为阻塞确认项，产品确认后转为正式回归用例 |

#### 验证点编写铁律

- ✅ **可观察、可判断**：`- 当输入X=100时，计算结果=200`
- ❌ **禁止模糊**：`系统正常`、`显示正确`
- ❌ **禁止合并**：一个验证点只检查一个逻辑行为
- ❌ **禁止臆造**：只基于需求原文
- ⚠️ **歧义标注**：`> 待确认：[具体问题]`

#### 边界场景输出规则
边界类用例可单独列为 `#### X.X 边界场景` 或独立子模块，至少覆盖：
- 边界值：最大值、最小值、0、等于阈值、超过阈值、负数、小数精度
- 数据边界：空数据、无记录、未配置
- 时间边界：跨周、跨月、跨年
- 范围边界：跨页、筛选后导出、历史快照与当前实时数据切换

### 执行流程

用户说 **"生成测试用例"** 后：

```
Step 1 扫描 → 列出当前目录所有需求文档，询问是否全部处理
Step 2 分析 → 提取模块/规则/边界/权限/公式/状态/链路/导出
Step 3 生成 → 按 功能场景 → 规则验证 → 边界场景 → 专项回归 顺序编排
Step 4 输出 → 保存文件，展示清单
```

#### 输出示例
```
✅ 已生成 3 个文件：
- 登录需求_测试用例.md（12条）
- 用户中心需求_测试用例.md（8条）
- 支付需求_测试用例.md（15条）
```

### 快捷指令

| 指令 | 作用 |
|:---|:---|
| `生成测试用例` | 处理所有需求文档 |
| `生成 [文件名] 的用例` | 只处理指定文档 |
| `补充 [文件名] 的用例` | 为已有用例补充场景 |

### 冲突处理

| 情况 | 处理 |
|:---|:---|
| 同名文件存在 | 询问：覆盖 / 追加 / 跳过 |
| 需求有歧义 | 添加 `> 待确认：[具体问题]` 标注 |

## 调度规则

测试用例生成仅使用**本地规则**（本文档 §测试用例生成规则）。

- 用户说「生成测试用例」→ 执行 Step 1→4，生成 `_测试用例.md`
- 用户说「生成 [文件名] 的用例」→ 只处理指定文档
- 用户说「补充 [文件名] 的用例」→ 读取已有用例，按九类场景和专项补充覆盖规则补充
