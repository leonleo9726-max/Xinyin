# 一、个人资料页模块

## 1.1 页面定位 / 功能说明

个人资料页模块是用户查看他人或自己公开资料的核心页面，负责展示用户基础信息、身份标签、公会信息、房间信息、荣耀勋章、支持者、礼物墙、动态内容，以及关注、私信、进入房间等关键操作入口。

该页面的核心目标：

1. 让访问者快速识别用户身份、等级、地区、公会、在线房间等关键信息。
2. 展示用户的社交关系数据，包括关注、粉丝、访客等统计入口。
3. 展示用户获得的勋章、标签、礼物墙和支持者信息，强化荣誉与付费关系沉淀。
4. 支持在个人信息和动态内容之间切换。
5. 支持从礼物墙预览进入完整礼物墙详情。
6. 支持从用户房间卡片或“正在房间”入口进入房间。
7. 支持关注、私信、拉黑等社交操作。

## 1.3 前置条件

| 场景 | 前置条件 | 处理方式 |
|---|---|---|
| 查看个人资料页 | 用户从搜索、榜单、聊天页、房间、支持者、动态等入口点击用户 | 加载用户公开资料信息 |
| 查看自己的资料页 | 当前用户进入自己的个人资料 | 展示本人资料，可按产品策略展示编辑入口 |
| 查看他人资料页 | 当前用户访问其他用户资料 | 展示关注、私信等社交操作 |
| 用户正在房间 | 被访问用户当前在房间内 | 展示“正在房间”入口 |
| 用户有创建房间 | 用户存在自己的房间 | 个人信息页展示我的房间卡片 |
| 用户无房间 | 用户没有创建房间 | 隐藏我的房间区块 |
| 用户有公会 | 用户当前加入公会 | 展示公会标签和公会信息卡片 |
| 用户无公会 | 用户未加入公会 | 隐藏公会信息区块 |
| 用户有礼物墙 | 用户收到过可展示礼物 | 展示礼物墙预览和详情入口 |
| 用户无礼物墙数据 | 用户无可展示礼物 | 礼物墙区块隐藏或展示空状态，按视觉方案执行 |
| 网络异常 | 资料加载失败 | 展示错误提示并允许重试 |

## 1.4 页面结构

个人资料页由以下区块 / 页面状态组成：

1. 顶部导航与背景图区域
2. 头像与基础资料区
3. 身份标签 / 等级标签 / 公会标签区
4. 社交统计区
5. 个人信息 / 动态切换区
6. 个人信息内容区
7. 我的房间区
8. 荣耀 / 勋章区
9. 公会信息区
10. 支持者区
11. 礼物墙预览区
12. 礼物墙详情页
13. 动态列表区
14. 底部关注 / 私信操作区
15. 更多操作区

## 1.5 页面字段定义

### 1.5.1 顶部导航与背景图区域

| 字段 / 元素 | 展示规则 | 交互规则 | 异常 / 空值处理 |
|---|---|---|---|
| 返回按钮 | 固定展示在左上角 | 点击返回上一页 | 无 |
| 更多按钮 | 固定展示在右上角 | 点击打开更多操作，如举报、拉黑、分享等 | 无可用操作时隐藏 |
| 背景图 | 展示用户个人主页背景图 | 点击可查看大图或进入资料编辑，具体按访问身份决定 | 未设置时展示默认背景图 |

| 复制按钮 | 用户 ID / 靓号旁展示复制入口 | 点击复制当前主展示的用户 ID 或靓号 | 复制失败时提示失败 |
| 国家 / 地区 | 展示国家 / 地区标识和文案 | 用户可在个人中心-个人资料中修改国家，但仅允许修改 1 次 | 无数据时隐藏 |

| 性别 | 展示性别图标 | 仅展示 | 未设置时隐藏 |
| 个性签名 | 展示用户个性签名 | 仅展示 | 未设置时显示为空或隐藏 |
| VIP 等级 | 展示用户 VIP 等级标签 | 点击可查看权益说明，按产品最终入口执行 | 无 VIP 时隐藏 |

## 1.6 统计 / 计算口径

### 1.6.1 用户 ID 展示口径

| 规则项 | 口径 |
|---|---|
| 普通用户 ID | 展示用户原始 ID |
| 靓号用户 | 若用户有靓号，全屏资料页主展示位优先展示用户靓号 |
| 靓号背景样式 | 显示靓号时，必须同时展示该靓号对应的标签背景样式 |
| 靓号背景来源 | 每个靓号支持服务端配置不同的靓号背景图，客户端不得写死靓号背景 |
| 复制内容 | 复制按钮复制当前页面主展示的可识别 ID；若主展示为靓号，则复制靓号 |
| 统一范围 | 用户资料页、用户房间、用户在线列表、公会展示的公会长 ID 均使用统一展示规则 |

### 1.6.2 支持者排序口径

| 规则项 | 口径 |
|---|---|
| 数据范围 | 给该用户累计送礼金额最高的用户 |
| 展示范围 | 历史送礼金额 TOP3 |
| 幸运礼物换算 | 幸运礼物按 10 金币 = 1 贡献值计入支持者贡献 |
| 支持者不足 3 人 | 对应名次展示空状态或按实际人数展示 |
| 展示字段 | 支持者头像、昵称、ID、财富等级、魅力等级等 |

### 1.6.3 礼物墙展示口径

| 规则项 | 口径 |
|---|---|
| 预览数量 | 个人资料页礼物墙预览限制展示 6 个 |
| 详情数量 | 礼物墙详情页展示完整礼物列表 |
| 礼物数量 | 展示用户累计收到该礼物的数量 |
| 灰态规则 | 数量为 0 或未点亮礼物可展示灰态 |
| 入口规则 | 点击礼物墙更多入口进入完整礼物墙详情页 |

### 1.6.4 标签与勋章排序口径

| 规则项 | 口径 |
|---|---|
| 标签来源 | 公会长、主播身份、自定义标签、服务端运营标签 |
| 标签样式 | 服务端配置图片 + 文本，文本允许为空 |
| 标签排序 | 有优先级按优先级排序，无优先级按标签获得时间降序 |
| 勋章排序 | 按获得勋章时间降序展示 |
| 客户端限制 | 标签样式和标签内容不能客户端写死 |

### 1.6.5 房间与公会展示口径

| 规则项 | 口径 |
|---|---|
| 房间信息 | 用户有房间时展示房间名称、封面、当前房间人数 |
| 无房间 | 隐藏我的房间区块 |
| 正在房间 | 用户当前在房间时展示顶部正在房间入口 |
| 公会信息 | 用户加入公会时展示公会封面、名称、ID |
| 无公会 | 隐藏公会信息区块 |

### 1.6.6 国家修改口径

| 规则项 | 口径 |
|---|---|
| 修改入口 | 用户在个人中心-个人资料中修改国家 |
| 修改次数 | 每个用户仅允许修改 1 次国家 |
| 已修改用户 | 已使用过国家修改机会后，国家字段不再允许再次修改 |
| 展示同步 | 国家修改成功后，个人资料页、用户卡片、搜索结果、榜单等展示用户国家的位置同步更新 |
| 失败处理 | 修改失败时保留原国家，不消耗修改次数 |

## 1.7 交互逻辑

### 1.7.1 进入个人资料页

1. 用户从搜索结果、榜单、聊天页、房间用户卡片、支持者卡片或动态入口点击用户。
2. 系统加载目标用户基础资料、标签、统计数据、房间状态、公会信息、礼物墙、动态等内容。
3. 页面优先展示顶部背景、头像和基础资料。
4. 默认进入个人信息或入口指定的页面状态。
5. 若资料加载失败，展示错误提示并允许重试。

### 1.7.2 基础资料与标签查看

1. 用户进入资料页后查看头像、昵称、ID、地区、年龄、性别、等级、签名等基础信息。
2. 若目标用户存在靓号，资料页主展示位显示用户靓号，并同时展示该靓号对应的标签背景样式。
3. 点击复制按钮，复制用户 ID 或靓号。
4. 点击公会标签或公会卡片，进入公会主页。
5. 点击等级标签或荣耀项，可进入等级说明或等级页
6. 标签按服务端配置展示，不允许客户端固定写死。

### 1.7.3 个人信息与动态切换

1. 点击“个人信息”。
2. 页面展示我的房间、荣耀、公会、支持者、礼物墙预览等内容。
3. 点击“动态”。
4. 页面切换到动态列表区。
5. 动态列表展示发布时间、文本、图片、评论数和点赞数。
6. 点击动态图片可查看大图或进入动态详情。
7. 点击评论或点赞，进入评论区或执行点赞 / 取消点赞。

### 1.7.4 房间入口交互

1. 用户资料页展示“正在房间”入口或我的房间卡片。
2. 点击正在房间入口或房间卡片。
3. 系统校验房间状态。
4. 房间可进入时，进入房间。
5. 房间关闭、封禁、回收、已满或用户无权限时，展示不可进入提示。

### 1.7.5 支持者交互

1. 页面展示历史送礼金额 TOP3 支持者。
2. 点击支持者头像、昵称或卡片。
3. 系统进入该支持者个人资料页。
4. 如果支持者账号异常或资料不可访问，展示不可访问提示。
5. 支持者不足 3 人时，空缺位按视觉方案隐藏或展示空状态。

### 1.7.6 礼物墙交互

1. 个人信息页展示礼物墙预览，最多 6 个礼物。
2. 点击礼物墙标题、右侧箭头或更多入口。
3. 页面进入礼物墙详情页。
4. 礼物墙详情页展示完整礼物网格。
5. 点击单个礼物时，可查看礼物详情，具体是否开放由产品最终方案决定。
6. 点击返回按钮，回到个人资料页。

### 1.7.7 关注与私信交互

1. 用户访问他人资料页。
2. 页面展示关注和私信入口。
3. 点击关注。
4. 系统执行关注操作，成功后刷新关注状态。
5. 点击私信或底部大私信按钮。
6. 系统校验双方聊天关系和私信权限。
7. 校验通过后进入聊天页面。
8. 若对方不可私信、当前用户被限制私聊或双方存在拉黑关系，展示不可私信提示。

### 1.7.8 更多操作与拉黑

1. 点击右上更多按钮。
2. 页面展示更多操作菜单。
3. 用户选择拉黑。
4. 系统展示拉黑确认流程。
5. 若当前用户具备房间管理相关权限，可展示“同时拉入房间黑名单”选项。
6. 用户确认后，系统执行拉黑操作，并按选择同步加入房间黑名单。
7. 拉黑成功后刷新资料页状态，私信和互动入口按限制规则处理。

## 1.8 状态定义

| 状态 | 触发条件 | 页面表现 | 用户可操作 |
|---|---|---|---|
| 加载中 | 进入个人资料页并请求数据 | 展示加载态 | 等待加载完成 |
| 正常资料状态 | 用户资料加载成功 | 展示完整基础资料、标签、统计和内容区 | 可切换、关注、私信、查看详情 |
| 资料不可访问 | 用户封禁、注销、资料隐藏或无权限查看 | 展示不可访问提示 | 可返回上一页 |
| 用户无房间 | 用户没有创建房间 | 隐藏我的房间区块 | 可继续查看其他资料 |
| 用户正在房间 | 用户当前在房间内 | 展示正在房间入口 | 可点击进入房间 |
| 用户无公会 | 用户未加入公会 | 隐藏公会标签和公会区块 | 可继续查看其他资料 |
| 礼物墙有数据 | 用户有可展示礼物 | 展示礼物墙预览 | 可进入详情页 |
| 礼物墙无数据 | 用户没有可展示礼物 | 隐藏礼物墙或展示空状态 | 可继续查看其他内容 |
| 动态有数据 | 用户发布过动态 | 展示动态列表 | 可查看图片、评论、点赞 |

| 支持者不足 | 历史送礼用户少于 3 人 | 按实际人数展示或展示空位 | 可点击已有支持者 |
| 已关注状态 | 当前用户已关注对方 | 关注按钮切换状态或隐藏 | 可按最终方案取消关注或保持已关注 |
| 不可私信状态 | 对方不可私信、双方拉黑或当前用户受限 | 私信入口置灰或点击提示 | 可返回或解除限制后再试 |
| 网络异常 | 资料或内容加载失败 | 展示错误提示 | 可点击重试 |

## 1.9 系统后台核心逻辑

1. 系统需要按用户维度返回个人主页基础资料，包括头像、背景图、昵称、ID、国家、年龄、性别、签名、等级和身份标签。
2. 用户昵称存在炫彩昵称权益时，系统返回对应展示状态，让页面按权益展示昵称效果。
3. 用户 ID 展示需要遵循全局统一规则：有靓号时，全屏资料页主展示位优先展示靓号。
4. 系统返回用户是否拥有靓号、靓号文案以及该靓号对应的背景图资源信息。
5. 每个靓号都需要支持服务端单独配置不同的靓号背景图，客户端不得按靓号类型写死背景样式。
6. 系统返回用户身份标签、公会标签、自定义标签以及标签样式和排序信息，客户端不得写死标签样式。
7. 系统返回用户社交统计，包括关注数、粉丝数和访客数；访客列表需要按用户权限进行访问控制。
8. 系统判断用户是否正在房间内，并返回可进入的房间信息。
9. 系统判断用户是否有自己的房间；有房间时返回房间封面、名称和当前人数，无房间时隐藏房间区块。
10. 系统判断用户是否加入公会；有公会时返回公会封面、名称和 ID，无公会时隐藏公会区块。
11. 支持者数据需要按历史累计送礼金额排序，取前三名；幸运礼物按 10 金币 = 1 贡献值折算。
12. 礼物墙预览最多返回 6 个可展示礼物，完整礼物墙详情返回完整礼物列表和数量。
13. 用户勋章需要按获得时间降序返回，超出展示区域时支持横向展示或跑马。
14. 动态列表需要返回发布时间、文本、图片、评论数、点赞数等字段，并支持图片查看和互动操作。
15. 用户资料页不再展示语音资料能力，相关旧入口需要移除。
16. 拉黑用户时，如果当前用户选择同时加入房间黑名单，系统需要同步处理房间黑名单关系，并刷新房间进入权限。
17. 关注、私信、进入房间、进入公会等操作前，系统校验目标用户、房间或公会是否仍可访问。
18. 系统记录用户国家修改次数；用户在个人中心-个人资料中仅允许成功修改 1 次国家，修改失败不消耗次数。

## 1.10 异常与测试关注点

| 场景 | 测试关注点 | 预期结果 |
|---|---|---|
| 资料页加载 | 是否完整展示头像、昵称、ID、标签、统计等信息 | 页面展示完整，不缺关键字段 |
| 用户有靓号 | 全屏资料页主展示位是否展示靓号 | 正确展示用户靓号 |

| 用户无公会 | 公会区块是否异常占位 | 隐藏公会标签和公会区块 |
| 用户有公会 | 是否能进入公会主页 | 点击公会标签或卡片进入公会主页 |
| 用户无房间 | 我的房间区是否隐藏 | 不展示空房间卡片 |
| 用户正在房间 | 正在房间入口是否展示 | 展示入口并可点击进入房间 |
| 房间不可进入 | 点击房间入口 | 展示不可进入提示，不强行进入 |
| 礼物墙超过 6 个 | 预览区是否只展示 6 个 | 预览限制 6 个，详情页展示完整列表 |

| 支持者不足 3 人 | 是否出现异常空卡 | 按实际人数展示或展示空状态 |

| 访客权限不足 | 点击访客列表 | 按 VIP 或权限规则拦截 |
| 私信不可用 | 点击私信入口 | 展示不可私信原因 |
| 拉黑用户 | 拉黑后互动入口是否刷新 | 私信、互动状态按拉黑规则限制 |

| 国家二次修改 | 已修改过国家后再次尝试修改 | 不允许再次修改，展示次数已用完提示 |
| 国家修改失败 | 修改国家时网络或服务异常 | 保留原国家，不消耗修改次数 |
| 网络异常 | 资料加载失败 | 展示错误提示并支持重试 |

# 二、直播间半屏消息模块

## 2.1 页面定位 / 功能说明

直播间半屏消息模块用于承接用户在直播间内查看消息的快捷能力，重点覆盖直播间底部消息入口、半屏消息列表、官方消息会话、用户消息会话、未读角标以及从直播间跳转到全屏聊天页 / 官方消息详情页的链路。

该模块的核心目标：

1. 在不离开直播间主页面的前提下，为用户提供快捷查看消息的半屏入口。
2. 明确直播间消息入口、未读角标和 `99+` 展示规则。
3. 明确半屏消息页中官方消息会话、用户消息会话的展示结构。
4. 明确点击用户消息后跳转全屏聊天页、点击官方 / 系统消息后进入对应消息详情页的交互链路。
5. 明确半屏消息页与全屏消息列表模块之间的能力继承关系，避免两套消息口径不一致。

## 2.3 前置条件

| 场景 | 前置条件 | 处理方式 |
|---|---|---|
| 查看消息入口 | 用户处于直播间主页面 | 底部展示消息入口 |
| 消息入口有未读 | 直播间消息存在未读 | 入口展示未读数量，超出 99 显示为 99+ |
| 打开半屏消息页 | 用户点击直播间底部消息入口 | 从页面底部拉起半屏消息列表，不离开直播间主页面 |
| 查看官方消息会话 | 官方 / 系统消息存在 | 在半屏消息列表顶部展示官方消息会话项 |
| 查看用户消息会话 | 用户存在可展示的聊天会话 | 在半屏列表中展示用户消息会话 |
| 点击用户消息会话 | 用户点击某个用户消息列 | 跳转与该用户的全屏聊天页面 |
| 点击官方 / 系统消息会话 | 用户点击官方消息行 | 进入对应官方 / 系统消息详情页，跳转规则沿用全屏消息列表模块 |

## 2.4 页面结构

直播间半屏消息模块由以下页面 / 状态组成：

1. 直播间底部消息入口与未读角标
2. 半屏消息面板头部
3. 官方消息固定会话区
4. 用户消息会话列表区
5. 半屏消息空状态 / 跳转状态

## 2.5 页面字段定义

### 2.5.1 直播间消息入口

| 字段 / 元素 | 展示规则 | 交互规则 | 异常 / 空值处理 |
|---|---|---|---|
| 消息入口 | 展示在直播间底部操作区，原型位于底部消息 / 信封类入口位置 | 点击后从底部拉起半屏消息列表 | 入口能力未开放时隐藏或不响应 |
| 未读角标 | 直播间消息存在未读时展示数字角标 | 仅展示，不直接清除未读 | 未读超过 99 时展示 `99+` |
| 默认状态 | 无未读时展示普通入口态 | 点击后仍可打开半屏消息列表 | 无可展示会话时打开空状态 |

### 2.5.2 半屏消息页头部

| 字段 / 元素 | 展示规则 | 交互规则 | 异常 / 空值处理 |
|---|---|---|---|
| 半屏面板 | 以 Bottom Sheet / 半屏抽屉形式从直播间底部拉起，顶部保留直播间背景可见区域 | 打开后覆盖直播间下半屏，不退出房间 | 拉起失败时保留直播间原状态 |
| 页面标题 | 固定展示“消息” | 仅展示 | 多语言按配置展示 |
| 收起 / 关闭入口 | 展示在头部右侧圆形按钮区域 | 点击后收起半屏消息页并返回直播间主视图 | 无法关闭时需支持系统返回或手势收起 |

### 2.5.3 半屏消息会话列表

| 字段 / 元素 | 展示规则 | 交互规则 | 异常 / 空值处理 |
|---|---|---|---|
| 官方消息会话 | 默认展示在列表顶部，原型示例为“官方消息”并带 `官方` 标签 | 点击进入对应官方 / 系统消息详情 | 无官方消息时按配置隐藏或展示默认入口 |
| 官方消息缩略图 / 图标 | 展示官方消息专属缩略图或系统图标 | 点击跟随官方消息会话跳转 | 图标失败时展示默认官方标识 |
| 官方消息摘要 | 展示最近一条官方消息内容摘要 | 点击查看完整内容 | 摘要超长时单行省略 |
| 官方消息时间 | 展示最近一条官方消息时间，原型示例为 `21:23` | 仅展示 | 无时间时隐藏 |
| 官方消息未读角标 | 官方消息存在未读时展示数字角标，原型示例为 `6` | 进入详情后按会话已读规则清除 | 无未读时隐藏 |
| 用户头像 | 展示消息会话对应用户头像 | 点击整行进入与该用户的全屏聊天页 | 头像为空时展示默认头像 |
| 用户昵称 | 展示消息会话昵称 | 点击整行进入全屏聊天页 | 昵称过长时截断 |
| 在线状态点 | 用户在线时展示绿色在线点 | 仅展示 | 离线时隐藏 |
| 最新消息摘要 | 展示最近一条消息内容摘要，原型示例为 `hi` | 点击整行进入全屏聊天页 | 摘要超长时单行省略 |
| 最新消息时间 | 展示该会话最新消息时间，原型示例为 `18:41`、`18:26` | 仅展示 | 无时间时隐藏 |
| 列表能力范围 | 功能口径同全屏消息列表模块 | 半屏页作为快捷入口，点击后进入对应完整消息页面 | 若能力配置受限，则按直播间版本开关处理 |

## 2.6 统计 / 计算口径

### 2.6.1 直播间消息入口未读口径

| 规则项 | 口径 |
|---|---|
| 未读展示位置 | 展示在直播间底部消息入口 |
| 未读统计范围 | 汇总直播间消息入口可见会话的未读数，当前至少覆盖官方消息会话和用户消息会话 |
| 超上限展示 | 超出 99 时统一展示 `99+` |
| 已读触发 | 进入具体会话或详情页后，按对应会话已读规则清除，不因单纯打开半屏列表而强制全部清零 |

### 2.6.2 半屏消息列表展示口径

| 规则项 | 口径 |
|---|---|
| 能力继承 | 功能同全屏消息列表模块 |
| 官方消息位置 | 官方消息会话固定展示在半屏列表顶部 |
| 用户会话排序 | 其他用户消息会话按最新消息时间倒序展示 |
| 摘要展示 | 统一展示单行摘要，超长省略 |
| 点击用户会话 | 跳转与该用户的全屏聊天页面 |
| 点击官方 / 系统消息 | 进入对应官方 / 系统消息详情页，后续业务跳转口径沿用消息列表模块 |

## 2.7 交互逻辑

### 2.7.1 打开直播间半屏消息页流程

1. 用户在直播间底部点击消息入口。
2. 页面从底部拉起半屏消息列表，上半屏仍保留直播间内容可见。
3. 半屏页头部展示“消息”标题和收起 / 关闭入口。
4. 列表优先展示官方消息会话，再展示用户消息会话列表。
5. 若无可展示消息，则展示半屏消息空状态。

### 2.7.2 点击半屏消息会话流程

1. 点击半屏列表中的某个用户消息列。
2. 系统跳转与该用户的全屏聊天页面。
3. 点击官方 / 系统消息会话时，进入对应官方 / 系统消息详情页。
4. 若消息配置了业务跳转，则详情页继续按全屏消息列表模块口径进入对应页面。
5. 进入具体会话后，对应未读状态按会话已读规则刷新。

### 2.7.3 关闭半屏消息页流程

1. 点击头部关闭入口、系统返回或收起手势。
2. 半屏消息页关闭，页面回到直播间主视图。
3. 已进入具体聊天页的情况不在本流程内处理，返回后再回到直播间。

## 2.8 状态定义

| 状态 | 触发条件 | 页面表现 | 用户可操作 |
|---|---|---|---|
| 消息入口默认状态 | 直播间消息入口无未读 | 展示普通消息入口 | 可点击打开半屏消息页 |
| 消息入口未读状态 | 存在未读消息 | 入口展示数字角标，超出 99 展示 `99+` | 可点击打开半屏消息页 |
| 半屏消息展开状态 | 用户点击消息入口 | 页面下半屏展示消息列表 | 可点击会话或关闭半屏页 |
| 官方消息会话状态 | 存在官方 / 系统消息 | 顶部展示官方消息会话项 | 可点击进入详情 |
| 用户消息会话状态 | 存在用户消息会话 | 展示头像、昵称、摘要、时间的会话列表 | 可点击进入全屏聊天页 |
| 半屏消息空状态 | 无可展示消息会话 | 展示空状态 | 可关闭返回直播间 |

## 2.9 系统后台核心逻辑

1. 系统支持直播间底部消息入口，并返回对应未读数量。
2. 消息入口未读数超过 99 时，统一按 `99+` 展示。
3. 直播间半屏消息列表能力需继承全屏消息列表模块的会话聚合、摘要、时间、未读和跳转规则。
4. 官方 / 系统消息会话需支持固定展示在半屏列表顶部，是否固定置顶由配置控制。
5. 点击用户消息会话后，系统应进入与该用户的全屏聊天页；点击官方 / 系统消息时，进入对应消息详情页。
6. 打开半屏消息列表本身不应强制把所有会话全部清零，具体已读仍按会话维度处理。
7. 关闭半屏消息页后，用户应回到原直播间，不得因打开半屏页而退出房间上下文。

## 2.10 异常与测试关注点

| 场景 | 测试关注点 | 预期结果 |
|---|---|---|
| 消息入口默认态 | 无未读时是否仍展示入口 | 展示普通消息入口 |
| 消息入口未读角标 | 未读数是否正确，超过 99 是否显示 `99+` | 角标正确展示 |
| 打开半屏消息页 | 是否从底部拉起，且不退出直播间 | 展示半屏消息列表，直播间上半屏仍可见 |
| 官方消息置顶 | 官方消息是否固定在半屏列表顶部 | 顶部展示官方消息会话 |
| 点击用户消息会话 | 是否进入对应全屏聊天页 | 正确跳转到对应用户聊天页 |
| 点击官方 / 系统消息 | 是否进入对应消息详情 | 正确打开官方 / 系统消息详情页 |
| 半屏消息空状态 | 无消息时是否有空状态 | 展示空状态并可关闭返回直播间 |
| 返回直播间 | 关闭半屏页后是否仍停留原房间 | 返回直播间主视图，不退出房间 |

# 四、直播间半屏资料页模块

## 4.1 模块说明与角色边界

直播间半屏资料页用于用户在不离开当前直播间的情况下，通过点击麦位用户或公屏用户打开资料浮层，快速查看用户基础信息、等级标签、身份标签、礼物墙和当前可执行操作。

该模块独立于全屏个人资料页：

1. 半屏资料页只承接直播间内的快速查看与即时操作。
2. 不承接全屏个人资料页中的动态、支持者、公会详情、完整礼物墙详情等重内容。
3. 半屏资料页中的基础资料、ID / 靓号、等级标签、身份标签、礼物墙等展示口径，需与全屏个人资料页保持一致。
4. 半屏资料页中的操作展示需受当前查看者角色、目标用户角色、目标是否在麦上、目标是否具备防踢权益、目标是否已被房间黑名单拦截等条件共同控制。

角色边界如下：

| 查看者角色 | 页面定位 | 可见操作范围 |
|---|---|---|
| 普通用户 | 快速查看他人资料并进行社交互动 | 关注、私聊、送礼、举报、拉黑 |
| 管理员 | 在普通用户能力基础上执行房间管理动作 | 禁言、闭麦、下麦、邀请用户上指定麦位、请离房 |
| 房主 | 在管理员能力基础上执行更高权限管理动作 | 设置管理员、取消管理员，以及其他房间管理动作 |

### 4.3.3 交互逻辑

1. 管理员在半屏资料页点击“邀请上麦”入口。
2. 系统弹出可选麦位列表，管理员选择指定麦位后发起邀请。
3. 目标用户收到邀请上麦请求，可选择接受或拒绝。
4. 目标用户拒绝或邀请超时，则本次邀请失效，不执行上麦。
5. 目标用户接受后，系统再次校验所选麦位当前是否为空。
6. 若所选麦位为空，则将目标用户上到该指定麦位。
7. 若所选麦位已有用户上麦，则取消本次上麦，并 Toast 提示：“该麦位已有用户上麦”。
1. 管理员点击直播间内目标用户后，系统打开管理员半屏资料页。
2. 页面先展示与普通用户一致的基础资料与社交能力。
3. 系统根据管理员身份、目标角色、目标是否在麦上、目标是否被禁言、目标是否具备防踢权益动态决定管理按钮展示。
4. 目标在麦上时，可展示闭麦、开麦、下麦等麦位相关操作。
5. 目标不在麦上时，可展示邀请用户上指定麦位等非麦上操作，隐藏仅限麦上用户的动作。
7. 管理员对房主、同级管理员等不可越权对象，不展示越权管理动作。

## 4.4 房主半屏资料页

![房主半屏资料页](1.0汇总原型图/个人资料页半屏-房主.jpg)

### 4.4.1 前置条件

|---|---|---|

| 房主查看管理员 | 目标用户当前为管理员 | 展示取消管理员等对应高权限操作 |
| 房主查看麦上用户 | 目标用户当前在麦上 | 展示麦位相关管理操作 |
| 房主查看非麦上用户 | 目标用户当前不在麦上 | 展示邀请用户上指定麦位等非麦上操作 |
| 目标用户具备防踢权益 | 目标用户 VIP 等级包含防踢权益 | 房主同样不可请离该用户 |

### 4.4.2 页面字段定义

| 字段 / 元素 | 展示规则 | 交互规则 | 异常 / 空值处理 |
|---|---|---|---|
| 基础资料区 | 展示规则与普通用户半屏资料页一致 | 沿用普通用户展示口径 | 沿用普通用户规则 |
| 管理员页全部管理操作 | 房主可见范围覆盖管理员可见范围 | 沿用管理员操作逻辑 | 沿用管理员规则 |
| 设置管理员按钮 | 目标用户当前不是管理员，且允许被设置管理员时展示 | 点击执行设置管理员 | 目标已是管理员时隐藏 |
| 取消管理员按钮 | 目标用户当前已是管理员时展示 | 点击执行取消管理员 | 目标不是管理员时隐藏 |
| 更高优先级房间管理动作 | 若原型存在额外高权限操作，房主可见 | 点击执行对应管理链路 | 不满足条件时隐藏 |

### 4.4.3 交互逻辑

1. 房主点击直播间内目标用户后，系统打开房主半屏资料页。
2. 页面展示基础资料、社交操作以及房主可见的全部管理动作。
3. 房主可对普通用户执行管理员级管理操作。
4. 房主查看管理员时，可展示取消管理员等高权限操作。
5. 房主查看普通用户时，可展示设置管理员能力。
6. 目标用户具备防踢权益时，房主同样不可执行请离房。
7. 房主查看自己时，不展示对自己生效的管理动作。

## 4.5 统一展示与权限口径

### 4.5.1 统一展示口径

| 规则项 | 规则说明 |
|---|---|
| 基础资料来源 | 半屏资料页的头像、昵称、ID / 靓号、个性签名、等级标签、身份标签、礼物墙等展示数据，需与全屏个人资料页口径一致 |
| 昵称展示 | 用户 VIP 含有炫彩昵称特权时，半屏页需展示炫彩昵称 |
| ID / 靓号展示 | 默认展示用户 ID；若用户持有靓号，则主展示位优先展示靓号 |
| 标签展示 | 展示用户财富等级、魅力等级、VIP 等级、用户身份标签、其他标签；其他标签最多展示两行，超出显示区域不展示 |
| 头饰框动效 | 用户头像装饰、头饰框等需要支持动效展示 |
| 礼物墙预览 | 半屏资料页展示礼物墙预览，不展示完整重内容；点击后进入完整礼物墙能力 |
| 房间上下文保持 | 打开、关闭半屏资料页不得导致用户退出当前直播间，也不得清空房间上下文 |

### 4.5.2 统一权限口径

| 规则项 | 规则说明 |
|---|---|
| 普通用户操作边界 | 普通用户只展示社交类操作，不展示房间管理动作 |
| 管理员操作边界 | 管理员可展示房间管理动作，但不可越权对房主或同级不可操作对象执行动作 |
| 房主操作边界 | 房主在管理员能力基础上，可执行设置管理员、取消管理员等更高权限操作 |
| 麦位状态联动 | 闭麦、开麦、下麦等动作仅对当前在麦上的目标展示；邀请用户上指定麦位等动作仅对当前不在麦上的目标展示 |
| 防踢规则 | 房间内用户 VIP 等级含有防踢功能时，管理员和房主均无法将该用户请离房间 |
| 房间黑名单规则 | 用户被拉入房间黑名单后，应被自动踢出且无法再次进入房间；被拉黑对象不再作为当前房间可操作目标展示 |

## 4.6 状态定义

| 状态 | 触发条件 | 页面表现 | 用户可操作 |
|---|---|---|---|
| 半屏资料页默认状态 | 用户点击目标用户且资料加载成功 | 展示对应角色半屏资料页 | 可查看资料并执行当前可见操作 |
| 查看自己状态 | 当前查看对象为自己 | 隐藏关注、私聊、送礼、举报、拉黑及对自己无意义的管理动作 | 仅可查看资料与关闭页面 |
| 目标不在麦上状态 | 目标用户当前不在麦上 | 隐藏仅限麦上用户操作 | 可执行非麦上用户操作 |
| 目标在麦上状态 | 目标用户当前在麦上 | 展示闭麦、开麦、下麦等麦位操作 | 可执行麦位管理动作 |
| 目标已被禁言状态 | 目标用户当前已被禁言 | 展示解除禁言按钮，隐藏禁言按钮 | 可解除禁言 |
| 目标具备防踢权益状态 | 目标用户 VIP 含有防踢权益 | 请离房按钮隐藏或置灰，并提示不可操作原因 | 不可执行请离房 |
| 房主查看管理员状态 | 房主查看当前管理员 | 展示取消管理员等房主专属动作 | 可执行高权限管理 |
| 管理员查看房主状态 | 管理员查看房主 | 隐藏越权管理动作 | 仅保留允许的查看或社交操作 |
| 目标离房状态 | 半屏页打开前或打开过程中目标用户离开房间 | 不展示资料页或自动关闭并提示 | 仅可关闭提示 |
| 网络异常状态 | 拉取资料或执行操作失败 | Toast 或错误提示，不退出直播间 | 可重试或关闭页面 |

## 4.7 系统后台核心逻辑

1. 系统根据当前查看者角色、目标用户角色、目标是否在麦上、目标是否被禁言、目标是否具备防踢权益等条件，动态返回半屏资料页展示内容与可执行操作。
2. 半屏资料页中的基础资料、ID / 靓号、等级标签、身份标签、礼物墙预览等展示数据，需要与全屏个人资料页保持同一业务口径。
3. 系统支持根据用户是否拥有炫彩昵称、头饰框、动效装饰等权益，返回对应展示效果。
4. 系统支持根据目标用户当前麦位状态，动态决定闭麦、开麦、下麦、邀请用户上指定麦位等管理操作是否展示。
5. 系统支持邀请用户上指定麦位的二段式流程：管理者选择目标麦位并发出邀请，目标用户接受后才执行实际上麦。
6. 目标用户接受邀请时，系统必须再次校验目标麦位是否为空；若麦位已被其他用户占用，则取消本次上麦，并 Toast 提示“该麦位已有用户上麦”。
5. 系统支持根据用户当前禁言状态，动态返回禁言或解除禁言操作。
6. 系统支持根据目标用户 VIP 权益判断防踢能力；具备防踢权益时，管理员和房主均不可请离该用户。
7. 系统支持房主对普通用户执行设置管理员，对现有管理员执行取消管理员，并在结果生效后同步房间管理身份状态。
8. 系统支持用户被加入房间黑名单后自动移出房间，并在后续半屏资料页操作中不再作为当前房间可操作目标返回。
9. 拉黑、举报、关注、私聊、送礼、禁言、闭麦、下麦、邀请用户上指定麦位、请离房、设置管理员、取消管理员等动作，均需要记录执行结果，并按既有业务规则处理失败与状态同步。
10. 打开或关闭半屏资料页不得导致当前用户退出直播间，也不得错误清空直播间上下文。

## 4.8 异常与测试关注点

| 场景 | 测试关注点 | 预期结果 |
|---|---|---|
| 三张原型引用 | 普通用户、管理员、房主原型是否都插入在对应小节下 | 三张原型均正确显示，无死链 |
| 普通用户查看他人 | 是否只展示关注、私聊、送礼、举报、拉黑 | 不展示房间管理动作 |
| 邀请上麦接受成功 | 管理员/房主邀请目标用户上指定麦位且目标接受 | 目标用户成功上到所选麦位 |
| 邀请上麦接受时麦位被占 | 目标用户接受邀请时所选麦位已有用户 | 取消上麦并 Toast 提示“该麦位已有用户上麦” |
| 邀请上麦拒绝 / 超时 | 目标用户拒绝邀请或邀请超时 | 不执行上麦，邀请状态失效 |
| 管理员查看普通用户 | 是否展示管理员可执行的房间管理动作 | 展示禁言、闭麦、下麦、邀请用户上指定麦位、请离房等允许动作 |
| 房主查看管理员 | 是否展示取消管理员等房主专属操作 | 房主专属动作正确展示 |
| 查看自己 | 是否隐藏对自己无意义的社交与管理按钮 | 仅展示资料查看与关闭能力 |
| 目标不在麦上 | 是否隐藏仅限麦上用户的动作 | 闭麦、下麦等按钮不展示 |
| 目标具备防踢权益 | 管理员、房主是否无法请离该用户 | 请离房不可执行 |
| 目标离房 | 目标已离房时是否还能打开半屏资料页 | 不打开或自动关闭并提示 |
| 资料一致性 | 半屏页与全屏资料页的昵称、ID / 靓号、标签、礼物墙是否一致 | 使用同一展示口径 |
| 黑名单拦截 | 目标用户被加入房间黑名单后是否仍能作为当前房间可操作目标出现 | 不再作为当前房间可操作目标展示 |
| 网络异常 | 拉取资料或执行操作失败时是否保留直播间上下文 | 只提示失败，不退出直播间 |
