# 公会需求 1.4 后台薪资需求文档 PRD 测试用例

## 1. 版本范围与页面结构
### 1.1 适用范围与命名
- 1.1.1 1.4 后台薪资功能仅覆盖“主播薪资”和“公会薪资”页面。
- 1.1.2 两页统一使用“非金币薪资”名称，不再展示旧名称。
- 1.1.3 两页薪资金额及可提现余额均以 USD 展示。
- 1.1.4 两页金币薪资字段展示美元金额，不展示金币数量。
- 1.1.5 两页钻石字段展示钻石数量，不附加 USD 单位。
- 1.1.6 主播薪资页面汇总区保留公会总非金币薪资、公会总金币薪资和公会总薪资。
- 1.1.7 主播薪资列表不展示公会总非金币薪资。
- 1.1.8 主播薪资列表不展示公会总金币薪资。
- 1.1.9 主播薪资列表不展示公会总薪资。
- 1.1.10 主播薪资列表的“可提现余额（含金币）”位于最右侧。
- 1.1.11 公会薪资页面保留公会总非金币薪资、公会总金币薪资和公会总薪资。
- 1.1.12 两页均不展示起始钻石余额。
- 1.1.13 两页均不展示最终钻石余额。
- 1.1.14 两页均不展示公会总薪资余额。
- 1.1.15 两页不展示预支、借支、待抵扣和对冲计算字段。
- 1.1.16 已删除业务不会因参考 1.0 页面结构而恢复。

### 1.2 只读边界
- 1.2.1 页面查询不触发工资结算。
- 1.2.2 页面排序不生成结算快照。
- 1.2.3 查看详情不触发余额入账。
- 1.2.4 导出不修改任一余额池金额。
- 1.2.5 页面不提供修改结算结果的操作入口。
- 1.2.6 页面不提供修改余额的操作入口。

## 2. 结算周期、归属与快照
### 2.1 月结与周结周期
- 2.1.1 月结周期按自然月统计。
- 2.1.2 自由政策（周结）按 UTC+3 自然周统计。
- 2.1.3 周结周期包含 UTC+3 周一 00:00:00 的数据。
- 2.1.4 周结周期不包含 UTC+3 下周一 00:00:00 的数据。
- 2.1.5 UTC+3 周日 23:59:59 的有效数据计入即将结束的自然周。
- 2.1.6 UTC+3 下周一 00:00:00 的有效数据计入新自然周。
- 2.1.7 每周一 UTC+3 00:00 结算上一自然周。
- 2.1.8 跨月自然周不按月末拆分。
- 2.1.9 跨年自然周不按年末拆分。
- 2.1.10 服务器本地时区变化不改变 UTC+3 周期边界。

### 2.2 当前结果与历史快照
- 2.2.1 当前未结束周期读取实时结算结果。
- 2.2.2 当前未结束周期不展示为“已结算”。
- 2.2.3 当前未结束周期的查询不生成历史快照。
- 2.2.4 当前未结束周期的查询不执行工资入账。
- 2.2.5 已结束且已结算周期读取对应结算快照。
- 2.2.6 历史记录的政策读取当期政策快照。
- 2.2.7 历史记录的公会归属读取当期归属快照。
- 2.2.8 历史记录的钻石输入读取当期结算快照。
- 2.2.9 历史记录的工资拆分读取同一结算快照版本。
- 2.2.10 当前政策变更后，历史工资不重算。
- 2.2.11 当前公会关系变更后，历史工资不重算。
- 2.2.12 当前余额变化后，历史工资快照不回写。

### 2.3 记录归属与生命周期
- 2.3.1 主播结算记录按“主播ID+周期+公会归属快照”区分。
- 2.3.2 公会结算记录按“公会ID+周期+结算快照版本”区分。
- 2.3.3 同一主播同一周期跨多个公会时按归属时间段拆成多条记录。
- 2.3.4 同一业务事件不得跨公会重复计入。
- 2.3.5 工资项保留工资项标识、归属对象和来源规则。
- 2.3.6 历史公会归属不被当前公会关系覆盖。
- 2.3.7 结算快照冻结政策、归属、输入、工资项和结果。
- 2.3.8 余额池按账号和余额池类型独立记录。
- 2.3.9 余额池当前值变化不修改已确认结算快照。
- 2.3.10 快照缺失或版本不一致时不拼接其他来源生成正常结果。

## 3. 钻石输入与政策计算
### 3.1 钻石输入
- 3.1.1 非幸运礼物按 `1金币=2钻石` 换算有效钻石流水。
- 3.1.2 幸运礼物按 `10金币=2钻石` 换算有效钻石流水。
- 3.1.3 冻结流水不计入有效钻石流水。
- 3.1.4 拒付流水不计入有效钻石流水。
- 3.1.5 其他无效流水不计入有效钻石流水。
- 3.1.6 有效流水按周期过滤。
- 3.1.7 有效流水按公会归属过滤。
- 3.1.8 有效流水按政策绑定快照过滤。
- 3.1.9 有效钻石流水仅作为公会长管理收益的计算输入。
- 3.1.10 有效钻石余额仅作为主播工资的计算输入。
- 3.1.11 系统不以有效钻石流水替代有效钻石余额计算主播工资。
- 3.1.12 系统不以有效钻石余额替代有效钻石流水计算公会长管理收益。
- 3.1.13 系统不使用公会总余额替代逐主播工资计算。
- 3.1.14 兑换钻石流水只汇总已确认兑换记录。
- 3.1.15 未确认兑换记录不计入兑换钻石流水。
- 3.1.16 兑换钻石流水不作为工资计算基数。
- 3.1.17 兑换钻石流水不用于推算有效钻石余额。

### 3.2 自由政策（月结）
- 3.2.1 自由政策（月结）主播总薪资使用“有效钻石余额×政策分成比÷钻石折算美元比例×主播分成比例”计算。
- 3.2.2 自由政策（月结）公会长管理收益使用“有效钻石流水×政策分成比÷钻石折算美元比例×公会长分成比例”计算。
- 3.2.3 政策分成比读取当期政策绑定快照。
- 3.2.4 钻石折算美元比例读取当期政策绑定快照。
- 3.2.5 主播分成比例读取当期政策绑定快照。
- 3.2.6 公会长分成比例读取当期政策绑定快照。
- 3.2.7 金币工资比例读取工资项对应的当期政策绑定快照。
- 3.2.8 有效钻石余额为 0 时主播总薪资为 0。
- 3.2.9 有效钻石流水为 0 时公会长管理收益为 0。
- 3.2.10 公会长兼主播时本人主播工资与管理收益分别生成工资项。

### 3.3 自由政策（周结）
- 3.3.1 周结主播工资使用自然周有效钻石余额计算。
- 3.3.2 当周有效钻石余额为 `13000000` 时，主播周总薪资为 `58.4 USD`。
- 3.3.3 当周有效钻石流水为 `13000000` 时，对应公会长周管理收益为 `21.6 USD`。
- 3.3.4 周结主播总薪资使用 `有效钻石余额×0.8÷130000×0.73` 计算。
- 3.3.5 周结公会长管理收益使用 `有效钻石流水×0.8÷130000×0.27` 计算。
- 3.3.6 周结金币工资比例使用 `0.2`。
- 3.3.7 周结结果不混入月结数据。
- 3.3.8 周结政策的历史结果读取当周政策快照。

### 3.4 TG政策（月结）
- 3.4.1 TG政策按公会月度流水命中当期政策档位。
- 3.4.2 档位参数读取当期政策绑定快照。
- 3.4.3 实际值等于当前档目标值时超档增量为 0。
- 3.4.4 实际值小于当前档目标值时不产生正向超档增量。
- 3.4.5 实际值超过目标值但不足一个超档步长时超档增量为 0。
- 3.4.6 实际值超过目标值一个完整步长时增加一个超档金额。
- 3.4.7 超过多个完整步长时使用向下取整后的步长数计算超档增量。
- 3.4.8 总工资基数等于当前档基础薪资加超档增量。
- 3.4.9 主播底薪使用主播有效钻石余额作为计算基数。
- 3.4.10 主播 TG 奖励使用主播有效钻石余额作为计算基数。
- 3.4.11 公会长分成使用主播有效钻石流水作为计算基数。
- 3.4.12 系统按政策比例拆出主播底薪 X、主播 TG 奖励 Z 和公会长分成 Y。
- 3.4.13 有效天未达标扣减沿用当期政策顺序。
- 3.4.14 扣减处理完成后再拆分金币与非金币工资。
- 3.4.15 页面不新增有效天扣减展示字段。
- 3.4.16 不同政策结果使用统一薪资字段展示，但计算基数不混用。

## 4. 金币拆分与汇总勾稽
### 4.1 工资项拆分
- 4.1.1 每笔主播工资项分别计算金币工资。
- 4.1.2 每笔主播工资项分别计算非金币工资。
- 4.1.3 每笔公会长管理收益工资项分别计算金币工资。
- 4.1.4 每笔公会长管理收益工资项分别计算非金币工资。
- 4.1.5 工资项金币工资等于工资项总额乘当期金币工资比例。
- 4.1.6 工资项非金币工资等于工资项总额乘“一减当期金币工资比例”。
- 4.1.7 系统不先汇总总额再倒拆金币与非金币工资。
- 4.1.8 同一工资项的金币工资与非金币工资之和等于工资项总额。
- 4.1.9 金币工资比例为 0 时金币工资为 0。
- 4.1.10 金币工资比例为 1 时非金币工资为 0。
- 4.1.11 工资项总额为 0 时金币与非金币工资均为 0。

### 4.2 角色汇总
- 4.2.1 主播非金币薪资等于各主播工资项非金币部分之和。
- 4.2.2 主播金币薪资等于各主播工资项金币部分之和。
- 4.2.3 主播总薪资等于主播非金币薪资加主播金币薪资。
- 4.2.4 公会长非金币分成薪资等于各管理收益工资项非金币部分之和。
- 4.2.5 公会长分成金币薪资等于各管理收益工资项金币部分之和。
- 4.2.6 公会长总薪资等于公会长非金币分成薪资加公会长分成金币薪资。
- 4.2.7 报表中的公会长总薪资只包含管理收益。
- 4.2.8 公会长本人主播工资计入主播总薪资。
- 4.2.9 公会长本人主播工资不重复计入公会长总薪资。

### 4.3 公会汇总
- 4.3.1 公会总非金币薪资等于主播非金币薪资加公会长非金币分成薪资。
- 4.3.2 公会总金币薪资等于主播金币薪资加公会长分成金币薪资。
- 4.3.3 公会总薪资等于公会总非金币薪资加公会总金币薪资。
- 4.3.4 公会总薪资等于主播总薪资加公会长总薪资。
- 4.3.5 多主播场景先逐工资项拆分再按公会汇总。
- 4.3.6 多政策工资项使用各自政策快照比例拆分后再汇总。
- 4.3.7 同一工资项在公会总账中只累计一次。
- 4.3.8 金币工资进入金币工资余额池。
- 4.3.9 金币工资只能用于提现金币出口。
- 4.3.10 非金币工资按既有工资型余额池出口规则使用。

## 5. 可提现余额（含金币）
### 5.1 主播实时余额
- 5.1.1 主播可提现余额包含当前个人薪资余额池的可提现部分。
- 5.1.2 主播可提现余额包含当前金币工资余额池的可提现部分。
- 5.1.3 主播可提现余额包含已实际入账且仍符合提现条件的转入薪资余额。
- 5.1.4 未实际入账的转入薪资不计入可提现余额。
- 5.1.5 已提现金额不计入可提现余额。
- 5.1.6 已冻结金额不计入可提现余额。
- 5.1.7 失败回滚尚未恢复的金额不计入可提现余额。
- 5.1.8 不可用金额不计入可提现余额。
- 5.1.9 无可用提现出口的金额不计入可提现余额。
- 5.1.10 金币工资计入展示值时不获得现金提现权限。
- 5.1.11 周期工资不会再次累计到转入薪资余额。
- 5.1.12 主播各余额池均为 0 时可提现余额展示 0 USD。
- 5.1.13 可提现余额直接读取当前余额池，不从本期工资推导。
- 5.1.14 历史周期页面仍展示当前实时可提现余额。
- 5.1.15 可提现余额大于周期总薪资时保持实际值。
- 5.1.16 可提现余额小于周期总薪资时保持实际值。
- 5.1.17 可提现余额与周期总薪资相等时仍按两个独立字段展示。
- 5.1.18 可提现余额明确标识为实时余额。

### 5.2 公会实时余额
- 5.2.1 公会可提现余额汇总明确归属于当前公会的主播实时可提现余额。
- 5.2.2 公会可提现余额汇总公会长管理收益对应的实时可提现余额。
- 5.2.3 公会长本人主播余额计入主播成员侧。
- 5.2.4 公会长管理收益余额与本人主播余额分开归因。
- 5.2.5 公会长多重身份不会导致同一余额池重复统计。
- 5.2.6 同一余额池不会跨多个公会重复统计。
- 5.2.7 公会实时余额不从公会总薪资反推。
- 5.2.8 查询公会实时余额不会创建独立公会钱包。
- 5.2.9 无法明确归因公会的余额不被猜测计入某个公会。
- 5.2.10 历史周期查询仍使用公会当前实时余额。
- 5.2.11 余额提现后页面刷新展示扣减后的实时值。
- 5.2.12 余额冻结后页面刷新不再把冻结部分计入可提现余额。
- 5.2.13 失败回滚恢复完成后页面刷新重新计入恢复金额。
- 5.2.14 实时余额变化不回写周期薪资快照。

## 6. 后台主播薪资页面
### 6.1 筛选与查询
- 6.1.1 公会ID支持精确查询。
- 6.1.2 输入不存在的公会ID时返回空状态。
- 6.1.3 公会ID为空时不限制公会范围。
- 6.1.4 公会名称支持模糊查询。
- 6.1.5 公会名称为空时不限制公会范围。
- 6.1.6 公会长ID按结算归属或当前关系查询对应记录。
- 6.1.7 主播ID支持主播级精确查询。
- 6.1.8 主播名称支持主播级名称查询。
- 6.1.9 政策结构包含“自由政策（月结）”。
- 6.1.10 政策结构包含“自由政策（周结）”。
- 6.1.11 政策结构包含“TG政策（月结）”。
- 6.1.12 仅选择月结政策时按自然月查询。
- 6.1.13 自由政策（月结）与 TG政策（月结）可按既有规则一起查询。
- 6.1.14 选择自由政策（周结）时日期切换为 UTC+3 自然周。
- 6.1.15 周结查询不混入月结政策记录。
- 6.1.16 所属大区筛选只改变数据范围，不改变工资计算结果。
- 6.1.17 结算状态筛选区分当前实时计算与已结算记录。
- 6.1.18 数据视图选择“结算快照”时只读取快照数据。
- 6.1.19 数据视图选择“实时数据”时只读取实时结果。
- 6.1.20 同一结果不拼接结算快照与实时数据。
- 6.1.21 点击查询后汇总与列表使用相同筛选条件。
- 6.1.22 点击查询后汇总与列表使用相同周期。
- 6.1.23 点击查询后汇总与列表使用相同数据源。
- 6.1.24 点击重置后清空公会、主播、政策和高级筛选输入。
- 6.1.25 点击重置后恢复默认周期和日期。
- 6.1.26 点击重置后清除已有排序状态。
- 6.1.27 查询无记录时清除上一查询的列表结果。
- 6.1.28 查询无记录时展示空状态。

### 6.2 汇总字段
- 6.2.1 汇总区钻石流水等于命中记录有效钻石流水之和。
- 6.2.2 汇总区钻石余额等于命中记录有效钻石余额之和。
- 6.2.3 汇总区钻石余额不使用起始或最终余额推导。
- 6.2.4 汇总区兑换钻石流水等于命中记录已确认兑换钻石之和。
- 6.2.5 汇总区主播非金币薪资等于命中主播工资项非金币部分之和。
- 6.2.6 汇总区主播金币薪资等于命中主播工资项金币部分之和。
- 6.2.7 汇总区主播总薪资等于主播非金币薪资加主播金币薪资。
- 6.2.8 汇总区可提现余额等于命中主播当前实时可提现余额之和。
- 6.2.9 汇总区公会长非金币分成薪资等于命中管理收益工资项非金币部分之和。

- 11.2.1 自由政策（周结）实际结算成功后向主播发送周工资结算完成消息。
- 11.2.2 月结政策不错误触发周工资结算消息。
- 11.2.3 主播周结消息展示实际公会名称、周开始日期、周结束日期和总薪资。
- 11.2.4 主播周结消息的日期范围与 UTC+3 自然周一致。
- 11.2.5 公会长周结个人工资实际结算成功后发送公会长周结消息。
- 11.2.6 公会长周结消息的个人薪资合计等于本人主播工资加公会长收益。
- 11.2.7 公会长周结消息分别展示本人主播工资和公会长收益。
- 11.2.8 公会长周结消息不跨周拼接金额。
- 11.2.9 公会长周结消息不跨公会拼接金额。
- 11.2.10 公会周结实际成功后向管理员发送公会周工资结算完成消息。
- 11.2.11 管理员周结消息不展示公会金额。
- 11.2.12 管理员本人存在主播工资时按主播身份接收对应消息。

### 11.3 工资转账消息
- 11.3.1 工资转账审核通过但收款账户未实际入账时不发送转账成功消息。
- 11.3.2 收款公会长账户实际入账成功后向转出主播发送“工资转账成功”。
- 11.3.3 转出主播消息展示实际转账金额、公会长昵称和公会长ID。
- 11.3.4 收款公会长账户实际入账成功后向收款公会长发送“主播工资转入到账”。
- 11.3.5 收款公会长消息展示实际主播昵称、主播ID和转账金额。
- 11.3.6 工资转账到账不额外通知管理员。
- 11.3.7 工资转账拒绝不发送成功消息。
- 11.3.8 工资转账入账失败不发送到账消息。

## 12. 系统消息：金币与现金提现
### 12.1 提现金币
- 12.1.1 金币实际发放成功后向申请人发送“提现金币到账”。
- 12.1.2 金币发放处理中不提前发送到账消息。
- 12.1.3 金币发放失败不发送到账消息。
- 12.1.4 金币消息展示申请提现的 USD 金额。
- 12.1.5 金币消息展示实际到账金币数。
- 12.1.6 实际到账金币数读取发放结果，不按当前比例重新换算。
- 12.1.7 金币工资全部提现与普通工资提现金币使用同一消息模板。
- 12.1.8 主播、公会长及管理员提现本人主播工资时均按申请人身份接收。

### 12.2 现金提现提交与审核
- 12.2.1 现金提现申请创建且金额冻结成功后发送“工资提现申请已提交”。
- 12.2.2 申请创建成功但冻结失败时不发送提交成功消息。
- 12.2.3 提交消息展示申请金额、提现方式和提现单号。
- 12.2.4 审核通过并进入待打款状态后发送“工资提现审核已通过”。
- 12.2.5 仅审核操作成功但未进入待打款状态时不发送审核通过消息。
- 12.2.6 审核通过消息展示申请金额、提现方式和提现单号。
- 12.2.7 审核拒绝结果确认后发送“工资提现申请未通过”。
- 12.2.8 审核拒绝消息展示申请金额、用户可见拒绝原因和提现单号。
- 12.2.9 冻结金额已释放时拒绝消息追加“本次申请冻结的金额已释放。”。
- 12.2.10 冻结金额尚未释放时拒绝消息不追加已释放文案。

### 12.3 现金打款成功
- 12.3.1 渠道或财务确认打款成功后发送“工资提现已打款”。
- 12.3.2 打款处理中不提前发送已打款消息。
- 12.3.3 打款成功消息使用“请留意到账情况”，不宣称已到账。
- 12.3.4 打款成功消息展示申请金额。
- 12.3.5 打款成功消息展示实际打款金额和实际打款币种。
- 12.3.6 实际打款金额不使用申请 USD 金额冒充。
- 12.3.7 打款成功消息展示提现方式和提现单号。
- 12.3.8 现金提现消息不展示收款账户。
- 12.3.9 现金提现消息不展示收款人。
- 12.3.10 现金提现消息不展示其他收款信息。

### 12.4 提现消息范围
- 12.4.1 现金提现仅新增提交待审核、审核通过待打款、审核拒绝和打款成功四类消息。
- 12.4.2 本次不新增现金到账确认消息。
- 12.4.3 本次不新增打款失败消息。
- 12.4.4 本次不新增失败回滚消息。
- 12.4.5 未新增消息不影响既有资金失败处理。

## 13. 消息幂等、边界与展示
### 13.1 幂等与触发时序
- 13.1.1 同一业务结果、同一接收人、同一消息场景只发送一次。
- 13.1.2 重复入会审核回调不重复发送入会结果消息。
- 13.1.3 结算任务重试不重复发送工资结算消息。
- 13.1.4 重复转账入账回调不重复发送转出和到账消息。
- 13.1.5 重复提现审核请求不重复发送审核结果消息。
- 13.1.6 重复金币发放回调不重复发送金币到账消息。
- 13.1.7 重复现金打款回调不重复发送已打款消息。
- 13.1.8 通知发送失败后的重试不重新执行工资结算。
- 13.1.9 通知发送失败后的重试不重新执行工资转账。
- 13.1.10 通知发送失败后的重试不重新发放资产。
- 13.1.11 申请通过消息不能由关系解除事件触发。
- 13.1.12 审核通过消息不能由实际打款事件替代触发。
- 13.1.13 实际入账消息不能由审核通过事件提前触发。
- 13.1.14 打款成功消息不能由提交申请事件提前触发。

### 13.2 消息范围与数据口径
- 13.2.1 本次不新增政策变更消息。
- 13.2.2 本次不新增结算延迟消息。
- 13.2.3 本次不新增工资更正消息。
- 13.2.4 本次不新增退会超时消息。
- 13.2.5 本次不新增工资转给公会长的拒绝消息。
- 13.2.6 本次不新增工资转给公会长的失败消息。
- 13.2.7 系统消息不扩展为短信。
- 13.2.8 系统消息不扩展为外部推送。
- 13.2.9 系统消息不新增消息跳转入口。
- 13.2.10 消息变量读取对应业务结果，不从当前余额反推历史金额。
- 13.2.11 消息变量读取对应业务结果，不从当前配置反推历史金额。
- 13.2.12 消息发送不改变工资计算结果。
- 13.2.13 消息发送不改变余额池。
- 13.2.14 消息发送不改变审核状态。

## 14. 多语言与数据质量
### 14.1 多语言展示
- 14.1.1 中文环境下两张薪资页面字段名称完整展示。
- 14.1.2 英文环境下两张薪资页面字段与金额不被截断。
- 14.1.3 阿拉伯语环境下两张薪资页面按 RTL 布局且列数据不错位。
- 14.1.4 阿拉伯语环境下筛选项、排序按钮和操作入口不重叠。
- 14.1.5 中、英、阿环境下 USD 与钻石单位不互换。
- 14.1.6 中、英、阿环境下完整政策名称与实际政策枚举一致。
- 14.1.7 系统消息中的昵称、公会名称和动态金额在中、英、阿环境下完整展示。
- 14.1.8 阿拉伯语消息中的数字、日期和币种顺序可读。

### 14.2 数据边界与质量
- 14.2.1 钻石输入为 0 时工资公式结果为 0。
- 14.2.2 负数钻石输入不作为正常工资记录展示并标记数据异常。
- 14.2.3 负数薪资结果不作为正常结算展示并标记数据异常。
- 14.2.4 重复主播结算记录不被重复汇总。
- 14.2.5 重复公会结算快照不被同时作为有效版本汇总。
- 14.2.6 缺少政策快照的记录不按当前政策补算。
- 14.2.7 缺少归属快照的记录不猜测归属到当前公会。
- 14.2.8 超大金额展示不遮挡相邻列或操作入口。
- 14.2.9 小数金额展示遵循现有账务精度，不在前端另行舍入。
- 14.2.10 列表分页切换后汇总仍覆盖完整筛选结果而非仅当前页。
- 14.2.11 跨页排序保持全量数据排序结果。
- 14.2.12 导出覆盖完整筛选结果，不只导出当前页。
