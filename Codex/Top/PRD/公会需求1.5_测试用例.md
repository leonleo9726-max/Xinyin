# 公会需求 1.5 测试用例

> 生成时间：2026-10-13
> 需求来源：公会需求1.5.md
> 格式：层次化清单（`- X.Y.Z 描述`）
> 测试点总数：208 个
> 口径调整：按 2026-10-13 确认，所有政策未达首档时均不触发工资结算，余额结转至下一周期；工资按结算时用户当前政策、当前有效余额计算，当前余额包含上周期转入余额。此口径覆盖来源文档中仅适用于普通政策的旧描述。

## 1. 全政策未达首档结转

### 1.1 政策与余额准入
- 1.1.1 普通政策主播在周期结束时执行首档判定，未达档则不触发工资结算。
- 1.1.2 自由政策（月结）主播在月结周期结束时执行首档判定，未达档则不触发工资结算。
- 1.1.3 自由政策（周结）主播在周结周期结束时执行首档判定，未达档则不触发工资结算。
- 1.1.4 已结算钻石不进入个人待结算钻石余额。
- 1.1.5 已计薪钻石不进入个人待结算钻石余额。
- 1.1.6 已失效钻石不进入个人待结算钻石余额。
- 1.1.7 按现行规则排除的钻石不进入个人待结算钻石余额。

### 1.2 首档边界
- 1.2.1 有效余额为 0 且低于首档时，不生成本周期工资结算记录。
- 1.2.2 有效余额比首档门槛少一个最小计量单位时，不命中首档。
- 1.2.3 有效余额等于首档门槛时，命中首档。
- 1.2.4 有效余额超过首档门槛时，命中对应档位。
- 1.2.5 任一政策未达首档时，不生成主播底薪 X 的结算结果。
- 1.2.6 任一政策未达首档时，不生成主播 TG 奖励 Z 的结算结果。
- 1.2.7 任一政策未达首档时，不生成对应公会长分成 Y 的结算结果。
- 1.2.8 任一政策未达首档时，不生成该主播对应的公会工资结算结果。
- 1.2.9 任一政策未达首档时，符合条件的有效钻石余额转为下一周期的个人待结算余额。
- 1.2.10 达到首档并结算成功后，本次计薪余额标为已计薪。
- 1.2.11 已计薪余额不进入下一周期的档位匹配。

### 1.3 跨周期累计与扣减
- 1.3.1 下一周期档位匹配余额包含上周期个人待结算余额。
- 1.3.2 下一周期档位匹配余额包含本周期新增有效余额。
- 1.3.3 本周期已消费钻石从档位匹配余额中扣除。
- 1.3.4 本周期已兑换钻石从档位匹配余额中扣除。
- 1.3.5 本周期已失效钻石从档位匹配余额中扣除。
- 1.3.6 本周期按现行规则不可参与结算的钻石从档位匹配余额中扣除。
- 1.3.7 连续两个周期均未达首档时，第二周期仍不触发工资结算。
- 1.3.8 连续两个周期均未达首档时，符合条件的余额继续结转。
- 1.3.9 自由政策（月结）未达档余额在跨月后参与下一月结周期的首档判定。
- 1.3.10 自由政策（周结）未达档余额在跨周后参与下一周结周期的首档判定。
- 1.3.11 历史结转余额参与普通政策主播 X/Z 档位匹配时，不生成当前周期新增钻石流水。
- 1.3.12 普通政策达档结算使用本次合并后的有效余额匹配 X 档位。
- 1.3.13 普通政策达档结算使用与 X 相同的主播侧档位匹配结果计算 Z。

### 1.4 政策变更后的结算
- 1.4.1 上周期未达档余额转入下一周期后，按结算时用户当前政策的首档门槛判定是否达档。
- 1.4.2 上周期未达档余额转入下一周期后，工资计算余额包含转入余额。
- 1.4.3 上周期未达档余额转入下一周期后，工资计算余额包含当期新增有效余额。
- 1.4.4 从普通政策切换为自由政策后，达档工资按结算时当前自由政策计算。
- 1.4.5 从自由政策切换为普通政策后，达档工资按结算时当前普通政策计算。
- 1.4.6 从自由政策（月结）切换为自由政策（周结）后，达档工资按结算时当前周结政策计算。
- 1.4.7 政策变更后，转入余额不按上周期政策单独计算工资。
- 1.4.8 政策变更后，使用当前政策结算不改写上周期未达档的结转记录。

## 2. 主播工资与公会长分成分离

### 2.1 达档结算
- 2.1.1 跨周期达档时，主播 X 使用达档时所在公会的当前有效普通政策。
- 2.1.2 跨周期达档时，主播 X 使用该主播结算时有效的 X 比例。
- 2.1.3 跨周期达档时，主播 Z 使用该主播结算时有效的 Z 比例。
- 2.1.4 新公会关系期间新增有效流水为 0、主播靠结转余额达档时，主播 X/Z 按普通政策生成。
- 2.1.5 新公会关系期间新增有效流水为 0、主播靠结转余额达档时，新公会长 Y 为 0 USD。
- 2.1.6 仅主播合并余额达档而新公会新增流水未达公会长侧档位时，不因主播 X/Z 大于 0 而生成 Y。
- 2.1.7 公会长 Y 的计算基数仅包含当前公会关系期间新增的有效钻石流水。
- 2.1.8 历史结转余额不进入公会长 Y 的计算基数。
- 2.1.9 旧周期流水不进入达档周期公会长 Y 的计算基数。
- 2.1.10 旧公会流水不进入新公会长 Y 的计算基数。

### 2.2 比例与快照
- 2.2.1 新公会修改主播 X 比例后，修改生效后尚未结算的工资使用新比例。
- 2.2.2 新公会修改主播 Z 比例后，修改生效后尚未结算的工资使用新比例。
- 2.2.3 比例修改不追溯重算已生成的主播结算快照。
- 2.2.4 跨公会结转余额达档时，主播 X/Z 不按旧公会与新公会比例拆分。
- 2.2.5 每项工资仍按现行规则拆分金币工资与非金币工资。

## 3. 离会与跨公会归属

### 3.1 关系解除时机
- 3.1.1 公会解散并实际解除关系后，主播待结算余额继续归本人。
- 3.1.2 公会长移除主播并实际解除关系后，主播待结算余额继续归本人。
- 3.1.3 主播退出申请通过且实际解除关系后，待结算余额继续归本人。
- 3.1.4 主播退出申请尚未通过时，不提前按已离会状态扣除旧公会流水。
- 3.1.5 移除流程尚未实际解除成员关系时，不提前发送关系解除通知。
- 3.1.6 离会后尚未加入新公会时，待结算余额仍可在主播账户查询。
- 3.1.7 离会后尚未加入新公会时，不产生任何新公会有效流水。
- 3.1.8 离会后尚未加入新公会时，不产生新公会长分成。
- 3.1.9 公会长本人作为主播的待结算余额在公会解散后仍归本人。
- 3.1.10 已计薪余额在离会后不回退为待结算状态。
- 3.1.11 主播工资余额在离会后仍归本人。
- 3.1.12 金币工资余额在离会后仍归本人。
- 3.1.13 可提现余额在离会后仍归本人。

### 3.2 新公会流水边界
- 3.2.1 关系生效前一刻产生的流水不计入新公会有效流水。
- 3.2.2 关系生效后一刻产生的有效流水计入新公会有效流水。
- 3.2.3 旧公会期间产生的原始流水仍保留原公会归属。
- 3.2.4 旧公会待结算余额进入新公会后，仅作为主播当前有效余额参与当前政策工资计算，不作为新公会有效流水。
- 3.2.5 旧公会待结算余额不计入新公会业绩。
- 3.2.6 旧公会待结算余额不计入新公会报表中的有效流水。
- 3.2.7 新公会关系生效后新增的有效余额与原待结算余额合并参与主播侧档位匹配。
- 3.2.8 同一周期内依次加入多个公会时，最终公会只统计其关系生效后的新增有效流水。
- 3.2.9 新公会政策为自由政策时，旧待结算余额纳入当前有效余额并参与该自由政策的首档判定。
- 3.2.10 新公会自由政策下当前余额达档时，主播工资按当前自由政策计算。

### 3.3 首次入会
- 3.3.1 从未加入公会的主播首次入会前已有余额不计入该公会有效流水。
- 3.3.2 首次入会前已有余额不参与该公会长 Y 计算。
- 3.3.3 首次入会前已有余额不计入该公会工资。
- 3.3.4 首次入会前已有余额不计入该公会业绩。
- 3.3.5 首次入会前已有余额不计入该公会报表。
- 3.3.6 首次入会操作不把入会前余额补录为公会流水。
- 3.3.7 首次入会后的新增有效流水按关系生效时间计入该公会。

## 4. 旧公会账面扣除与追溯

### 4.1 扣除范围
- 4.1.1 关系解除时，旧公会本周期尚未结算的该主播有效流水从工资账面排除。
- 4.1.2 被账面扣除的流水不进入旧公会本周期最终有效流水汇总。
- 4.1.3 被账面扣除的流水不生成旧公会长 Y。
- 4.1.4 被账面扣除的流水不补发旧公会长 Y。
- 4.1.5 被账面扣除的流水不保留对应旧公会长 Y 成本。
- 4.1.6 被账面扣除的流水对应主播工资不计入旧公会总薪资。
- 4.1.7 被账面扣除的流水对应公会长分成不计入旧公会总薪资。
- 4.1.8 账面扣除不减少主播个人待结算钻石余额。
- 4.1.9 关系解除前已结算的历史周期不被账面扣除。
- 4.1.10 关系解除前已计薪余额不迁移为待结算余额。

### 4.2 留痕与历史
- 4.2.1 账面扣除后，原始钻石流水仍可查询。
- 4.2.2 扣除记录保留原流水产生时间。
- 4.2.3 扣除记录保留原归属公会和政策。
- 4.2.4 扣除记录保留扣除原因和扣除时间。
- 4.2.5 扣除记录关联对应主播和离会事件。
- 4.2.6 离会归属快照冻结旧公会关系及政策。
- 4.2.7 后续加入新公会不改写旧公会离会归属快照。
- 4.2.8 页面查询不把已扣除流水重新计入旧公会工资账面。
- 4.2.9 导出重跑不把旧公会流水归入新公会。
- 4.2.10 后台重算不把旧公会流水归入新公会。

## 5. 公会解散

### 5.1 批量收口
- 5.1.1 解散不为成员生成新的普通离会工资结算。
- 5.1.2 解散成功后，原公会长与原公会的当前关系解除。
- 5.1.3 解散成功后，管理员与原公会的当前关系解除。
- 5.1.4 解散成功后，主播与原公会的当前关系解除。
- 5.1.5 解散时当前周期未结算流水从旧公会工资账面排除。
- 5.1.6 解散后未完成的加入申请关闭并记录“公会已解散”。
- 5.1.7 解散后未完成的退出申请关闭并记录“公会已解散”。
- 5.1.8 解散完成后，原公会长可按现行资格创建或申请加入公会。
- 5.1.9 解散完成后，原主播可按现行资格创建或申请加入公会。
- 5.1.10 解散后已结算周期的公会、成员和政策历史快照仍可查询。
- 5.1.11 解散后已结算周期的工资、余额和提现历史快照仍可查询。

### 5.2 不可变快照与重试
- 5.2.1 解散完成前生成包含操作人、原因和时间的不可变快照。
- 5.2.2 解散快照保存解散时成员名单、角色和关系解除生效时间。
- 5.2.3 解散快照保存当前政策、版本及主播 X/Z 比例。
- 5.2.4 解散快照保存每位主播待结算余额和已计薪状态。
- 5.2.5 解散快照保存当前周期原始流水及账面扣除结果。
- 5.2.6 解散快照保存已生成工资、余额池及提现、冻结、失败回滚资金状态。
- 5.2.7 解散快照保存关闭的申请及关闭原因。
- 5.2.8 批量解绑部分失败时，成功成员的处理结果保留。
- 5.2.9 批量解绑部分失败时，失败成员保持“解散处理中”。
- 5.2.10 批量重试只处理未成功成员。
- 5.2.11 批量重试不重复扣除已成功成员的旧公会账面。

## 6. 客户端与后台薪资展示

### 6.1 当前与历史
- 6.1.1 未达首档时，主播当前薪资页不展示本周期已生成工资结算结果。
- 6.1.2 未达首档时，主播当前薪资页显示个人待结算钻石余额。
- 6.1.3 未达首档时，主播当前薪资页显示余额结转至下一周期的结果说明。
- 6.1.4 主播历史记录显示当期未达首档的结转结果。
- 6.1.5 主播历史记录不把未达首档的结转结果展示成工资结算记录。
- 6.1.6 当前余额变化后，历史结转余额仍显示当期快照值。
- 6.1.7 公会薪资页不展示未达首档主播对应的已生成主播工资。
- 6.1.8 公会薪资页不展示未达首档主播对应的已生成公会长分成。
- 6.1.9 公会薪资页不把未达档余额计作公会工资基数。

### 6.2 后台详情
- 6.2.1 后台主播薪资详情显示本期有效钻石余额。
- 6.2.2 后台主播薪资详情显示首档命中结果。
- 6.2.3 后台主播薪资详情显示结转前与结转后余额。
- 6.2.4 后台主播薪资详情显示未触发工资结算的原因及结转记录版本。
- 6.2.5 后台公会薪资详情可追溯对应主播原始流水。
- 6.2.6 后台公会薪资详情不计入未达档主播对应的 Y 或其他已结算公会工资。

## 7. 提现申请审核新增字段

### 7.1 政策筛选
- 7.1.1 “提现时政策”多选筛选位于“角色类型”之后。
- 7.1.2 “提现时政策”筛选默认显示“全部”。
- 7.1.3 不选择具体政策时，列表不按政策过滤。
- 7.1.4 选择“全部”时，列表不按政策过滤。
- 7.1.5 选择 TG 政策时，列表只返回提现时政策为 TG 政策的申请。
- 7.1.6 选择自由政策（月结）时，列表只返回提现时政策为自由政策（月结）的申请。
- 7.1.7 选择自由政策（周结）时，列表只返回提现时政策为自由政策（周结）的申请。
- 7.1.8 同时选择多个具体政策时，列表返回政策属于任一选中项的申请。
- 7.1.9 政策筛选与审核状态等现有筛选条件同时生效。
- 7.1.10 政策筛选结果为空时，列表不显示其他政策的申请。

### 7.2 列表与导出
- 7.2.1 列表“提现时政策”列位于“提现渠道”之后。
- 7.2.2 列表“提现时政策”列位于“收款账号”之前。
- 7.2.3 列表展示申请发起时保存的结算政策。
- 7.2.4 申请后政策变更不改写已有申请的政策展示。
- 7.2.5 导出结果包含“提现时政策”字段。
- 7.2.6 导出同笔申请的政策值与列表一致。
- 7.2.7 导出范围同时应用当前政策筛选和其余列表筛选条件。
- 7.2.8 列表当前页之外的符合筛选条件记录按现行导出范围规则导出。
- 7.2.9 政策筛选结果为空时，导出不混入其他政策记录。
- 7.2.10 政策筛选操作不改变提现申请状态。
- 7.2.11 政策筛选操作不改变审核、打款或余额处理结果。

## 8. 状态流转、幂等和中断

### 8.1 余额状态
- 8.1.1 各政策周期内新增可计薪余额进入“正在累计”。
- 8.1.2 任一政策未达首档时，余额进入下一周期“待结算”。
- 8.1.3 达档并开始工资结算时，余额从“待结算”进入“结算锁定”。
- 8.1.4 结算锁定期间，同批余额不能进入第二个结算任务。
- 8.1.5 工资结算成功后，锁定余额进入“已计薪”。
- 8.1.6 工资结算失败后，锁定余额恢复“待结算”。
- 8.1.7 已计薪余额不能回退“待结算”。
- 8.1.8 同主播、同政策周期、同余额批次重复触发时，仅有一条结转结果。
- 8.1.9 同一余额批次并发结算时，仅有一个任务成功消费该批余额。
- 8.1.10 结算失败后重试复用原结算记录，不重复生成工资。
- 8.1.11 结算失败后重试不重复扣除待结算余额。

### 8.2 离会扣除与中断
- 8.2.1 同一离会事件、主播、旧公会和周期重复处理时，仅生成一条账面扣除记录。
- 8.2.2 离会任务重试不重复扣除旧公会本周期流水。
- 8.2.3 关系解除失败时，不按已解除关系发送通知。
- 8.2.4 解散批量任务中断后，重试读取已保存的快照和成员处理状态。
- 8.2.5 结转后发生提现时，历史未达首档快照不变。
- 8.2.6 结转后发生冻结时，历史未达首档快照不变。
- 8.2.7 结转后发生失败回滚时，历史未达首档快照不变。
- 8.2.8 提现、冻结或失败回滚后的当前有效余额按现行资产有效性规则参与结算。
