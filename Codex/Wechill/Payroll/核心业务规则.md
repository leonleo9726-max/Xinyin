# 核心业务规则 (Payroll Rules)

> **中东区与英语区共用同一公式框架，仅档位数值不同。**

---

## 1. 政策类型矩阵（所有地区通用）

| 特性 | 自由政策 (Liberal) | 双周政策 (Bi-weekly) |
| :--- | :--- | :--- |
| **超档计算** | 适用 (分母: **16026**) | 适用 (分母: **25000**) |
| **超档分配** | 主播 75% / 公会长 25% | **主播 100%**（公会长不参与） |
| **公会长奖励列** | 有 | 无 |
| **准入门槛** | 无 (低于等级1按超档计，档位视为 0) | 无 (低于等级1按超档计，档位视为 0) |
| **结算精度** | **两位小数，直接截断 (Floor)** | **两位小数，直接截断 (Floor)** |

## 2. 未达标罚则（所有地区通用）

主播未达个人目标时，**先按原始流水正常计算，再对结果打折**：

| 步骤 | 操作 |
| :--- | :--- |
| 1 | 按原始钻石流水套入公式，正常计算所有字段 |
| 2 | 最终薪资 = 步骤1 结果 × **0.7**，逐字段截断 |

| 角色 | 打折范围 |
| :--- | :--- |
| **主播薪资** | host salary、TG reward、Host total 各 × 0.7 |
| **公会长分成** | agent shared salary × 0.7 |

> 达标判定以主播个人目标为准（由运营设定，不在档位表内）。各字段打折后仍需截断到规定精度。
> **惩罚适用范围**：双周政策下英语区与中东区统一适用，不合格成员（无论 role=0/1/2）所有字段 ×0.7。自由政策默认达标，无惩罚。

### 2.1 结算周期

| 周期 | 范围 |
| :--- | :--- |
| **上半月** | 每月 1 号 ~ 15 号 |
| **下半月** | 每月 16 号 ~ 月末最后一天 |

用于双周政策达标判定中的**新成员免罚**判断：`app_user_agency_member.join_time` 若在当前结算周期内，该成员免于惩罚。

#### 2.1.1 首周期保护（ratio 判定优先级最高）

加入公会后的第一个结算周期，**无论是否达标，salary_ratio 一律 = 1.00**。

```sql
-- 判定：join_time > 周期起始时间 → 首周期，ratio = 1.00
SELECT join_time FROM app_user_agency_member
WHERE user_id = ? AND status = 1;
-- 如果 join_time > '?start' → 首周期保护生效，不受有效天数影响
```

### 2.2 达标数据源与 salary_ratio 判定

查 `stay.app_live_user_site_daily_summary` 表。

**ratio 判定优先级（由高到低）：**
1. **首周期保护** → ratio = 1.00（见 §2.1.1）
2. **达标** → 有效天数 ≥ 6 **且** 总时长 ≥ 12 小时 → ratio = 1.00
3. **未达标** → 不满足以上任一 → ratio = 0.70

```sql
-- 有效天数 & 总时长查询
SELECT
  COUNT(CASE WHEN duration >= 7200 THEN 1 END) AS effective_days,
  ROUND(SUM(duration) / 3600, 2) AS total_hours
FROM app_live_user_site_daily_summary
WHERE user_id = ? AND dates BETWEEN '?start' AND '?end';
-- effective_days >= 6 且 total_hours >= 12 → ratio = 1.00，否则 = 0.70
```

## 3. 通用公式框架

**超档钻石** = 总流水 − 档位收钻（低于等级1 时档位收钻 = 0）
**超档薪资总额** = 超档钻石 ÷ 超档分母

### 3.1 档位独立判定规则

**主播**与**公会长**使用不同的流水值独立查档：

| 角色 | 档位判定基数 | 超档基数 | 说明 |
|:---|:---|:---|:---|
| 主播 | `gain_diamond + send_gain_diamond` | `gain_diamond + send_gain_diamond` | 主播的钻石总余额 |
| 公会长 | `gain_coin`（本期净增，见 §3.2） | `gain_coin`（本期净增） | 公会长分成基数，结算不跨期清零，需取本期净增 |

两者可处于不同档位。查档后各自使用所属档位的薪资、奖励及超档门槛。

### 3.2 公会长佣金计算基数

公会长分成使用 **`gain_coin`**，但与 `gain_diamond` 同理——`app_user_account.gain_coin` 是**历史累计总额**，结算不会清零。当前周期实际分成基数需扣除周期初余额：

**当前周期 gain_coin = `app_user_account.gain_coin` − 周期初 gain_coin**

> **为什么不能直接用字段值？** `gain_coin` 跨周期累加不重置（与 Diamond target 同理）。例如数据库 gain_coin = 10,900,000，其中 4,000,000 是上期结转，本期净增仅 6,900,000 —— 直接用 10,900,000 会严重高估会长档位和佣金。

**获取方式：**

1. **优先**：查 `app_user_coin_detail` 表，coin_type=1，汇总本周期业务流水；需先排除“周期起始历史结算清算扣减”（见下方规则），其余正、负向业务流水均保留
2. **备选**：用当前 `gain_coin` 减去周期初快照值（需提前记录），仅在有快照时可用
3. **历史周期**：用结算记录表的对应字段或归档表还原

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|:---|:---|:---|:---|:---|
| 周期起始历史结算清算扣减排除 | `source_type=18`、`option_type=203`、`remark='host salary'`、`coin<0` 且发生在周期开始后 10 分钟内 | `period_gain_coin = SUM(coin) - SUM(匹配清算扣减的 coin)` | `[start, start + 10 minutes)` | 所有地区、所有政策 |

> 该扣减用于清空**上一周期**结算余额，不是本周期产生的公会长分成基数。不得因该条记录将本期 `gain_coin` 判为负数或标为待复核；其他负向业务流水不得排除，仍需进入复核。

```sql
-- 本期 gain_coin 净增（半开区间；排除周期起始历史结算清算扣减）
SELECT IFNULL(SUM(
  CASE
    WHEN source_type = 18
     AND option_type = 203
     AND remark = 'host salary'
     AND coin < 0
     AND create_time >= ':start'
     AND create_time < DATE_ADD(':start', INTERVAL 10 MINUTE)
    THEN 0
    ELSE coin
  END
), 0) AS period_gain_coin
FROM app_user_coin_detail
WHERE user_id = :user_id
  AND coin_type = 1
  AND create_time >= ':start'
  AND create_time < ':end_exclusive';
```

> **会长佣金基数 = 本期 gain_coin 净增**，用该值查会长档位、计算超档。历史周期的结算记录中 agency_owner_salary 已固化当时计算值，直接取用即可。

### 3.3 Current Diamond target（本期钻石流水）数据源

**页面显示的 Diamond target 不是单表字段，是三部分聚合计算：**

| 组成部分 | 数据源 | SQL |
|:---|:---|:---|
| ① 当前钻石余额 | `app_user_account.gain_diamond + send_gain_diamond` | 直接查账户表 |
| ② 本周期已结算钻石 | `app_payer_host_salary_detail_v2` WHERE status=2 AND settlement_time BETWEEN | `SUM(diamonds)` |
| ③ 兑换金币花掉的钻石 | `app_payer_diamond_purchase_detail` WHERE create_time BETWEEN | `SUM(spent_diamonds)` |

**Diamond target = ① + ② + ③**

> **为什么需要三部分？** 结算打款会清零钻石余额，只看余额会低估实际流水。公式 = 当前剩余 + 已被结算扣走的 + 兑换花掉的 = 本周期真实钻石流水。

```sql
-- ① 当前余额
SELECT gain_diamond + send_gain_diamond AS 当前余额
FROM app_user_account WHERE user_id = ?;

-- ② 本周期已结算
SELECT IFNULL(SUM(diamonds), 0) AS 已结算钻石
FROM app_payer_host_salary_detail_v2
WHERE user_id = ? AND status = 2
  AND settlement_time BETWEEN '?start' AND '?end';

-- ③ 兑换花掉的钻石
SELECT IFNULL(SUM(spent_diamonds), 0) AS 兑换花掉
FROM app_payer_diamond_purchase_detail
WHERE user_id = ?
  AND create_time BETWEEN '?start' AND '?end';
```

> **注意**：当前周期档位判定用 `gain_diamond + send_gain_diamond`（余额）即可，Diamond target 主要用于页面展示。历史周期因余额已清零，必须用三源加总还原真实流水。

## 4. 自由政策 (Liberal) 计算（所有地区通用）

> **默认达标**：自由政策默认视为已达标，不触发未达标罚则（×0.7）。仅当用户明确指定「未达标」时才执行罚则。

| 字段 | 公式 |
| :--- | :--- |
| **host salary** | 档位主播工资 + 超档薪资总额 × 0.75 |
| **TG reward** | 档位主播奖励 |
| **Host total salary** | host salary + TG reward |
| **agent shared salary** | 档位公会长工资 + 超档薪资总额 × 0.25 + 档位公会长奖励（基数按 §3.2 gain_coin） |

> 低于等级1: 档位视为 0，所有档位薪资=0，仅计算超档。

## 5. 双周政策 (Bi-weekly) 计算（所有地区通用）

| 字段 | 公式 |
| :--- | :--- |
| **host salary** | 档位主播工资 + 超档钻石 ÷ 25000 |
| **TG reward** | 档位主播奖励 |
| **Host total salary** | host salary + TG reward |
| **agent shared salary** | 档位公会长工资（基数按 §3.2 gain_coin） |

> 低于等级1: 档位视为 0，全量按超档计算。

## 6. 地区档位表

> **档位数据以数据库 `app_payer_salary_v2_config` 表为准。** 计算时必须实时查询该表获取档位值，严禁硬编码。下表仅作参考用途。

### 6.1 查询方式

```sql
-- 按结算政策类型和地区查询档位配置
SELECT `level`, diamonds, host_salary, agency_owner_salary,
       host_tg_reward, agency_owner_tg_reward, excess_diamonds_rate
FROM stay.app_payer_salary_v2_config
WHERE settlement_policy_type = ?   -- 1=双周, 2=自由
  AND region = ?                   -- 0=英语区, 2=中东区
ORDER BY `level` ASC
```

### 6.2 表结构

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `settlement_policy_type` | int | 1=双周政策, 2=自由政策 |
| `region` | int | 0=英语区, 2=中东区 |
| `level` | int | 档位等级 |
| `diamonds` | bigint | 收钻门槛 |
| `host_salary` | decimal(10,2) | 档位主播工资 |
| `agency_owner_salary` | decimal(10,2) | 档位公会长工资 |
| `host_tg_reward` | decimal(10,2) | 档位主播 TG 奖励 |
| `agency_owner_tg_reward` | decimal(10,2) | 档位公会长 TG 奖励 |
| `excess_diamonds_rate` | bigint | 超档分母（当前仅双周政策有效，自由政策固定使用 16026） |

## 7. 公会薪资计算 (Agency Salary)

字段来源参见 `公会薪资计算规则.md`（主播视角 / 公会长视角），本节定义计算公式。

### 7.1 主播级薪资字段（每个主播独立计算）

| 字段 | 计算公式 |
| :--- | :--- |
| **Host salary（档位基础工资）** | 档位主播工资 + 超档主播薪资（政策决定），不含 TG |
| **TG Reward** | 档位主播奖励 |
| **Host total salary（主播总工资）** | (Host salary + TG Reward) × salary_ratio |
| **Salary balance（工资余额）** | Host total salary − Host Advance Salary |
| **agent shared salary** | 档位公会长工资 + 超档公会长薪资 + 档位公会长奖励（政策决定） |
| **Host Advance Salary** | 该主播累计预支欠款（实时，取 `app_user_account.advance_salary_total_amount`） |

### 7.2 公会级薪资汇总

| 字段 | 计算公式 |
| :--- | :--- |
| **All hosts Salary** | Σ(全体成员 Host total salary)，含公会长自身主播薪资 |
| **Agent Commission** | Σ(全体成员 agent shared salary)，含公会长自身 agent shared |
| **Agency total Salary** | Σ(全体成员 Host total salary) + Agent Commission |
| **Agency Advance Salary** | Σ(各主播 Host Advance Salary) + Agent Advance Salary |
| **Agency total Salary Balance** | Agency total Salary − Agency Advance Salary（字段值不会为负数） |

### 7.3 公会长主播身份薪资

公会长自身作为主播时的独立薪资，与佣金分开计算：

| 字段 | 计算公式 |
| :--- | :--- |
| **Agent as host Salary** | 公会长主播身份 Salary balance（档位基础 + 超档佣金），不含 TG |
| **Agent TG Reward** | 公会长主播身份 TG Reward |
| **Agent as host Advance Salary** | 公会长主播身份预支欠款 |
| **Agent Commission** | Σ(全体成员 agent shared salary) |
| **Agent total salary** | Agent as host Salary + Agent TG Reward + Agent Commission |
| **Agent borrowed amount** | 公会长**本期**借支金额。06-12 口径：本期最后一次结算之后的借支（查 `admin_content_agency_borrow_salary_log` type=1 求和），结算后清零，未还部分结转至历史欠款 |
| **Agent borrowable amount** | **直接读** `app_user_agency.borrowable_amount`（美元）。字段为滚动余额：借支审批通过时已原子扣减、结算还款时加回，切勿再减本期借支/历史欠款（06-09~06-12 期间双扣 Bug 根源） |
| **Agent Salary Balance** | Agent total salary − Agent as host Advance Salary（不再减借支，借支与薪资独立） |

### 7.4 公会长盈余模块（新增）

公会长结算页面独立模块，区分系统结算（双周）与手动结算（自由政策）。

#### 7.4.1 盈余字段

| 字段 | 计算公式 |
| :--- | :--- |
| **本期薪资** | Agent as host Salary + Agent TG Reward + Agent Commission（= Agent total salary − 本期预支） |
| **本期借支** | 本期内最后一次结算之后的借支金额，查 `admin_content_agency_borrow_salary_log`（type=1，金额美元），结算后清零 |
| **本期实际工资** | 本期薪资 − 本期借支 − 历史欠款 |
| **历史欠款** | 取 `app_payer_agency_owner_surplus` 最新一条归档：若 `period_actual_salary < 0` 则为 `ABS(period_actual_salary)`，否则为 0 |
| **本期盈余** | 本期薪资 − 本期借支（盈余汇总） |

#### 7.4.2 结算结转规则

| 条件 | 行为 |
| :--- | :--- |
| 本期实际工资 **< 0** | 本期薪资、本期借支、本期实际工资三者**清零**；差额绝对值结转至**下期历史欠款** |
| 本期实际工资 **>= 0** | 正常结算；下期历史欠款 = 0（已还清） |

#### 7.4.3 结算类型

| 类型 | 触发场景 |
| :--- | :--- |
| **系统结算** | 双周政策自动结算 |
| **手动结算** | 自由政策手动触发结算，确认弹窗含历史账单记录字段 |

## 8. 单位换算警示

数据库金额字段**有的存美元、有的存分**，搞错差 100 倍。对不上时先查单位：

| 字段 | 所在表 | 存储单位 | 页面单位 | 换算 |
|:---|:---|:---|:---|:---|
| `advanced_amount` | `app_payer_host_salary_detail_v2` | **分** | 美元 | ÷ 100 |
| `borrowed_amount` | `app_payer_host_salary_detail_v2` | **分** | 美元 | ÷ 100 |
| `borrowed_amount` | `app_user_agency` | 美元 | 美元 | 无需换算 |
| `borrowable_amount` | `app_user_agency` | 美元 | 美元 | 无需换算 |
| `duration` | `app_live_user_site_daily_summary` | **秒** | 小时 | ÷ 3600 |
| `advance_salary_total_amount` | `app_user_account` | 美元 | 美元 | 无需换算 |
| `withdrawal_balance` | `app_user_account` | 美元 | 美元 | 无需换算 |
| `host_salary` / `actual_salary` / `agency_owner_salary` 等 | 结算记录表 / 配置表 | 美元 | 美元 | 无需换算 |

### 8.1 预支金额的双源差异（容易踩坑）

| 周期 | 数据源 | 字段 | 单位 |
|:---|:---|:---|:---|
| **当前周期** | `app_user_account` | `advance_salary_total_amount` | **美元**（直接读） |
| **历史周期** | `app_payer_host_salary_detail_v2` | `advanced_amount` | **分**（÷100 = 美元） |

> 同一概念（预支金额），当前周期和历史周期的取值路径和单位完全不同。
