# BDM 核心业务规则

## 1. 角色与状态枚举

| 字段 | 值 | 含义 |
|------|-----|------|
| BD.status | 试用/转正 | 在职，有BD端权限 |
| BD.status | 离职 | 无BD端权限，视为普通用户 |
| BD.position | BD | 绑定BD政策，归属BDM，有公会目标考核 |

## 2. 有效薪资流水（BD薪资核心公式）

### 2.1 流水来源
公会长公会分成薪资、公会分成TG、自由政策主播手动结算底薪、自由政策主播手动结算TG

### 2.2 底薪有效薪资流水
```
底薪有效薪资流水 = Σ(每个公会: 当前自然月 ∩ 绑定有效期 ∩ 底薪有效区间 的达标流水)
  - 窗口内流水 ≥ 门槛(默认300$) → 全额计入
  - 窗口内流水 < 门槛 → 0
  - 到期日当天不计入（左闭右开）
```

### 2.3 Bonus有效薪资流水
```
Bonus有效薪资流水 = Σ(每个公会: 当前自然月 ∩ 绑定有效期 ∩ Bonus有效区间 的达标流水)
  - 门槛规则同底薪(默认300$)
  - 到期日当天不计入（左闭右开）
```

### 2.4 跨月
不得跨月重复累计历史有效期流水。

## 3. BD薪资计算

```
本月底薪           = 底薪有效薪资流水 → 匹配底薪等级表 → 取底薪值
本月公会提成       = Bonus有效薪资流水 × 等级提成比例
本月总薪资         = 本月底薪 + 本月公会提成
本月总薪资余额     = 本月总薪资 - 新增公会未达标扣款
可提现薪资         = 累计已结算薪资 - 所有已成功提现金额  // 金币+现金共池
```

---

## 4. BDM薪资计算

```
团队底薪有效薪资流水  = Σ(下属BD底薪有效薪资流水) + BDM本人BD公会底薪流水
团队Bonus有效薪资流水 = Σ(下属BD Bonus有效薪资流水) + BDM本人BD公会Bonus流水
BDM本月底薪           = 团队底薪有效薪资流水 → BDM底薪等级表 → 取底薪值
BDM本月公会提成       = 团队Bonus有效薪资流水 × BDM提成比例
BDM本月总薪资         = BDM本月底薪 + BDM本月公会提成
```

**双轨**：BDM团队薪资（管理收益）与 BDM个人BD薪资（本人公会）分开展示、分开结算，但本人公会业绩同时参与管理收益计算。BDM团队薪资**无"总薪资余额"**字段，**不适用新增公会未达标扣款**。

---

## 5. 等级匹配

```
等级 = max(上月Bonus有效薪资流水, 本月Bonus有效薪资流水) → 匹配等级表 → 取最高达标Level
```
- 只升不降
- 新BD 初始 = **Level 1**
- 底薪等级 & 提成等级 分轨计算

---

## 6. 有效期 +15 天

- **触发**：公会首次绑定时间 ∈ [16日 00:00:00, 月末] → 底薪/Bonus/金币奖励/游戏币奖励 到期日各 **+15天**
- **不触发**：首次绑定 ∈ [1日, 15日] → 严格按配置自然月
- 16号后绑定，最后一次结算仅统计首个周期薪资

---

## 7. 新增公会考核 & 扣款

> **适用范围**：仅 BD 政策。BDM 政策无此扣款逻辑。

```
新增公会条件（三者 AND）：
  1. 首次创建时间 ∈ 本月
  2. 首次绑定成功时间 ∈ 本月
  3. 首次绑定BD = 当前BD

当月新增数 < 配置目标 → 扣款 = (底薪 + 提成) × 扣款比例
当月新增数 ≥ 配置目标 → 不扣
```
- 换绑/转移/重新分配 **不计入** 新增

---

## 8. 结算周期

```
上半月：[1日 00:00:00, 16日 00:00:00)
下半月：[16日 00:00:00, 下月1日 00:00:00)
```
- 主播变更公会 → 按周期结算 → 薪资归最终所在公会及对应BD

## 9. 提现规则

| 维度 | 金币提现 | 现金提现 |
|------|----------|----------|
| 最低限额 | 1$ | 50$ |
| 开放时间 | 无限制 | 仅每月 3-7 号 |
| 到账方式 | 即时到账，无需审核 | 审核制（审核中→已到账/已拒绝） |
| 余额冻结 | 即时扣减 | 提交不冻结，审核通过时复检扣减 |
| 手续费 | 无 | USDT ≤1$/笔 |
| 方式 | - | USDT/Bank/Vodafone/Shamcash |
| 汇率 | 服务端配置（默认11800），客户端禁止硬编码 | - |
| 余额池 | **金币+现金共池** | **同左** |

---

## 10. 公会换绑BD

```
校验：目标BD在职 + 同大区 + 公会未解散 + 目标≠当前
效果：
  - 保留旧绑定历史，创建新绑定
  - 不重置底薪/Bonus有效期
  - 当月数据归新BD/新BDM（不切割）
  - 不计入新BD本月新增数
  - 不重算历史结算单
```

## 11. BD薪资查询展示规则

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|------|------|------|------|------|
| 当前月BD薪资来源 | 查询当前自然月 BD 个人薪资 | `bd_realtime_staff_salary`，筛选 `salary_role=1`、`total_salary>0`，并限定 `bd_staff.role_bd=1` | `salary_role=1`=BD个人薪资 | BD政策；双角色人员仅展示其 BD 个人薪资 |
| 历史月BD薪资来源 | 查询已结算月份 | `bd_staff_monthly_salary`，筛选 `salary_role=1` | `salary_role=1`=BD个人薪资 | 历史结算快照；不得与实时表混用 |
| 身份展示 | 展示人员角色 | `role_bd=1 && role_bdm=1` 显示“BD+BDM”；仅 `role_bd=1` 显示“BD” | 身份以 `role_bd` / `role_bdm` 为准 | BD查询不展示 `salary_role=2` 的 BDM 团队管理薪资 |
| 预支与借支展示 | 展示当前未结清债务 | `bd_staff_salary_debt` 按 `staff_id` 关联；可借支金额=`borrow_limit_amount-borrowed_amount` | 无债务记录显示“无债务记录”，不可直接补零 | 当前实时债务汇总 |
| 薪资余额口径 | 展示当前月薪资余额 | 直接展示 `total_salary_balance` | 无 | 不得再减去预支金额或借支金额；两者属于独立快照 |

### 11.1 展示字段

| 展示分组 | 字段 |
|------|------|
| 人员 | `salary_month`、`user_number`、`display_name`、BD/BDM身份、在职状态、`bd_level` |
| 薪资 | `base_effective_flow`、`bonus_effective_flow`、`base_salary_amount`、`bonus_share_reward`、新增/有效新增公会数、两类未达标扣款、`total_salary`、`total_salary_balance`、`coin_reward`、`game_coin_reward` |
| 债务 | `advance_total_amount` 展示为 **预支金额**；`borrowed_amount` 展示为 **借支金额**；`borrow_limit_amount` 展示为借支额度；`borrow_limit_amount-borrowed_amount` 展示为可借支金额 |

### 11.2 查询质量门禁

- 查询前检查 `bd_staff_monthly_salary_issue`：当前结算月 `issue_status=1` 时，结果须单独标注为 **异常声明**。
- 导出或展示前先确认列名及前 3 行；有薪资人员、薪资字段、债务字段均需完整列出，不截断。
