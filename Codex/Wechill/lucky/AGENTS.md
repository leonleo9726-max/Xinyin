# AGENTS.md — 幸运礼物子项目规范

本文件适用于 `lucky/` 及其子目录；与项目根 `AGENTS.md` 冲突时，以本文件为准。未覆盖事项继承根规范。

## 1. 规则入口

- 处理幸运礼物配置、抽奖、概率、轨道、用户统计、周奖池、对账或故障排查时，先完整读取 `幸运礼物业务规则.md`。
- `幸运礼物业务规则.md` 是本目录唯一业务知识入口，已合并产品规则、实现结构、已知差异和未决口径。
- 用户临时提供的新需求、开发说明或验收材料仅用于当次核对；确认后的长期口径合并进 `幸运礼物业务规则.md`，不保留对临时文件的依赖。

## 2. 工作流程

1. 确认问题属于配置、抽奖、用户策略、周奖池、客户端展示或报表，并定位对应规则章节。
2. 查询表前执行 `SHOW COLUMNS FROM <表名>`；查询 Redis 前确认 key 参数及 UTC+3 日期边界。
3. 读取数据后先展示列名及前 3 行，再执行质量巡检。
4. 数据核验按 `配置主表 -> 规则表 -> 规则选择 -> 抽奖轨道 -> 用户统计 -> 周奖池 -> 报表` 的链路交叉验证。
5. 将产品要求、实现事实、数据观测和待确认项分开表述。
6. 对阈值执行边界核验，并同时检查业务值、内部精度和比较符；测试值必须能按 x10 倍率或万分之一概率真实入库。
7. 发现新字段、枚举、表关系、阈值或公式后，当次更新 `幸运礼物业务规则.md`；完成标准为长期口径已自包含、冲突已显式记录且无重复定义。

## 3. 数据源与身份口径

- 默认使用测试库 MCP `mysql` 的 `stay` 库；只有用户明确要求生产库时才使用 `mysql_prod`。
- 用户输入的数字默认视为 `user_number`，先通过用户表解析 `user_id`；只有用户明确说明时才按 `user_id` 查询。
- Redis 检查默认使用项目配置的测试 Redis。

## 4. 核心约束

- 配置化幸运礼物要求 `mechanism_type = 1`；`0` 或空值属于旧 `LANE` 机制。
- `status = 0` 的礼物幸运配置直接不中奖；该状态与礼物上下架状态分别核验。
- 普通规则使用 `lane_rule_id` 且 `newcomer = 0`；新人规则使用 `newcomer_lane_rule_id` 且 `newcomer = 1`。
- 倍数采用 x10 精度，概率采用万分之一精度，规则概率总和必须为 `10000`。
- 配置化轨道 key 使用规则 ID：`payer:gift:luck:configured:track:{giftId}:{ruleId}`；旧文档中的规则 JSON hash 不是当前口径。
- 日、周统计边界统一按 UTC+3；周从周一开始。
- Redis 是周奖池实时运行态，数据库 `released_amount` 由定时任务异步回刷；比较时必须标注采样时间与异步窗口。

## 5. 输出要求

- 使用简体中文，结论先行。
- 业务规则使用 `Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy` 五字段表格。
- 数据异常在结论前以“**异常声明**”单独列出。
- 概率同时展示内部值和百分比；倍数同时展示内部值和业务倍数。
- 数据查询结果完整展示，不截断影响结论的行。
