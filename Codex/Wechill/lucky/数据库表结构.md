# Lucky 数据库表结构

> 数据环境：测试库 `stay`；最后核验：2026-09-18。
> 本文记录幸运礼物用户筛选、余额调整、审核状态和安全等级操作涉及的用户表及 Redis 缓存。幸运礼物配置、概率、奖池和报表规则仍以 `幸运礼物业务规则.md` 为准。

## 1. 查询约定

- 用户输入的数字默认是 `app_user.user_number`；只有明确说明时才按 `user_id` 查询。
- 用户表之间统一按 `user_id` 关联。
- 手机号由 `area_code` 与 `phone_number` 分列存储；查询 `+86` 手机号必须同时限制 `area_code = '86'`。
- 注册时间取 `app_user.create_time`。测试库不存在 `app_user_register`，不要继续探查该表。
- 本项目当前“阿语用户”筛选口径为 `app_user_profile.language = 'ar'`；不要用 `first_language` 或 `app_language` 替代。
- 金币余额取 `app_user_account.coin`；`gain_coin` 是获得金额，不是可消费金币余额。
- 非审核用户为 `app_user_flag.audit_status = 0`。
- 一级用户为 `app_user_flag.safe_level = 1`；`safe_type` 是安全用户类型，不是用户等级，禁止互替。
- 直接修改用户账户或标记后，必须同步 Redis `user:info:{user_id}` 并分别回读 MySQL 与 Redis 校验。
- 本文中的 `UPDATE` / `HSET` 模板仅限测试环境且需用户明确授权；生产环境必须走正式业务接口或经批准的数据修复流程。
- 每次查询前仍需执行 `SHOW COLUMNS FROM <表名>`，防止线上结构变更后继续使用旧文档。

## 2. 表关系

```text
app_user.user_id
  |-- app_user_profile.user_id   语言、时区、国家、公会属性
  |-- app_user_account.user_id   金币、钻石、冻结余额、累计值
  |-- app_user_flag.user_id      审核状态、安全类型、安全等级、区域
  |-- app_user_location.user_id  定位国家与经纬度
  `-- app_user_number.user_id    历史/靓号记录

Redis user:info:{user_id}        用户聚合缓存（Hash）
```

`app_user.user_number` 是当前用户显示 ID 的权威字段。`app_user_number` 可保存一个用户的多条号码记录，不能直接替代主表当前值。

## 3. 用户主表

### 3.1 `app_user`

用户基础表；主键为 `user_id`，`user_number` 唯一。

| 字段 | 类型 | 空值/默认值 | 含义 |
|---|---|---|---|
| `user_id` | bigint | NOT NULL, AUTO_INCREMENT | 内部用户 ID |
| `user_number` | bigint | NOT NULL, UNIQUE | 用户显示 ID（`user_no`） |
| `login_type` | smallint | NOT NULL | 登录类型，枚举待确认 |
| `area_code` | varchar(10) | NULL | 电话区号，不含 `+` |
| `phone_number` | varchar(20) | NULL | 手机号本地号码 |
| `login_email` | varchar(100) | NULL | 登录邮箱 |
| `login_unique_id` | varchar(64) | NULL | 登录设备码 |
| `password` | varchar(64) | NULL | 密码摘要 |
| `salt` | varchar(64) | NULL | 加密盐 |
| `sex` | tinyint | NOT NULL, 0 | 0=未知，1=女，2=男 |
| `avatar` | varchar(256) | NULL | 头像 |
| `nickname` | varchar(50) | NULL | 昵称 |
| `birthday` | datetime(3) | NULL | 生日 |
| `modify_type` | bigint | NULL | 修改标识，位运算 |
| `status` | tinyint | NOT NULL, 1 | 0=禁用，1=启用，2=注销 |
| `comp_info` | tinyint | NOT NULL, 0 | 是否完善资料 |
| `update_time` | datetime(3) | NOT NULL | 更新时间 |
| `create_time` | datetime(3) | NOT NULL | 注册时间 |
| `migration_source_user_id` | bigint | NULL | 英语区迁移来源旧用户 ID |

主要索引：`user_number` 唯一索引；`(phone_number, area_code)`、`create_time`、`nickname`、`login_email`、`login_unique_id` 普通索引。

## 6. Redis 用户缓存

| 项目 | 值 |
|---|---|
| Key | `user:info:{user_id}` |
| 类型 | Hash |
| 用户 ID 字段 | `userId` |
| 用户号字段 | `userNumber` |
| 手机字段 | `areaCode`、`phoneNumber` |
| 金币字段 | `coin` |
| 审核字段 | `auditStatus` |
| 安全类型字段 | `safeType` |
| 安全等级字段 | `safeLevel` |

关键 MySQL/Redis 映射：

| MySQL | Redis Hash 字段 |
|---|---|
| `app_user.user_id` | `userId` |
| `app_user.user_number` | `userNumber` |
| `app_user.area_code` | `areaCode` |
| `app_user.phone_number` | `phoneNumber` |
| `app_user_account.coin` | `coin` |
| `app_user_flag.audit_status` | `auditStatus` |
| `app_user_flag.safe_type` | `safeType` |
| `app_user_flag.safe_level` | `safeLevel` |

缓存同步命令模板：

```text
HSET user:info:{user_id} coin {coin}
HSET user:info:{user_id} auditStatus 0 safeLevel 1
HMGET user:info:{user_id} coin auditStatus safeType safeLevel
```

不得使用 `KEYS` 扫描 Redis；定位用户缓存时直接构造精确 key。批量写入后逐 key 回读，不能只依据 `HSET` 返回值判定成功。

## 7. 常用查询模板

### 7.1 最近注册的阿语用户

```sql
SELECT
    CASE
        WHEN u.phone_number IS NULL THEN NULL
        WHEN u.area_code IS NULL OR u.area_code = '' THEN u.phone_number
        ELSE CONCAT('+', u.area_code, u.phone_number)
    END AS phone,
    u.user_id,
    u.user_number AS user_no,
    u.create_time
FROM app_user u
JOIN app_user_profile p ON p.user_id = u.user_id
WHERE p.language = 'ar'
ORDER BY u.create_time DESC, u.user_id DESC
LIMIT 200;
```

### 7.2 按 `+86` 手机号查询金币余额

```sql
SELECT
    u.phone_number,
    u.user_id,
    u.user_number AS user_no,
    a.coin
FROM app_user u
LEFT JOIN app_user_account a ON a.user_id = u.user_id
WHERE u.area_code = '86'
  AND u.phone_number IN ('手机号1', '手机号2')
ORDER BY FIELD(u.phone_number, '手机号1', '手机号2'), u.user_id;
```

### 7.3 修改金币余额

```sql
UPDATE app_user_account
SET coin = :target_coin
WHERE user_id IN (:user_ids);

SELECT user_id, coin
FROM app_user_account
WHERE user_id IN (:user_ids)
ORDER BY user_id;
```

MySQL 校验通过后，再将每个 `user:info:{user_id}` 的 `coin` 写为相同值并回读。

### 7.4 修改为非审核、一级用户

```sql
UPDATE app_user_flag
SET audit_status = 0,
    safe_level = 1,
    update_time = NOW(3)
WHERE user_id IN (:user_ids);

SELECT user_id, audit_status, safe_type, safe_level, update_time
FROM app_user_flag
WHERE user_id IN (:user_ids)
ORDER BY user_id;
```

MySQL 校验通过后，同步 Redis：`auditStatus=0`、`safeLevel=1`。不要修改 `safe_type` / `safeType`，除非用户明确要求改变安全用户类型。

## 8. 数据质量门禁

- 批量操作前确认输入条数、匹配用户数、重复手机号数和缺失账户/标记记录数。
- 查询结果先展示列名及前 3 行确认结构；手机号、账户或缓存字段为空时单列“异常声明”。
- 修改前记录目标用户原值；修改后校验 `匹配数 = 目标数 = Redis 回读成功数`。
- Redis MCP 超时时，不得将未确认状态报告为成功；恢复连接或通过同一测试 Redis 的受控客户端完成写入和回读。
- 写入后等待后台同步窗口再次检查 MySQL，防止互相冲突的字段触发后台回写。
- 本文只记录已核验事实；未确认枚举继续标记为“待确认”，不得推断。
