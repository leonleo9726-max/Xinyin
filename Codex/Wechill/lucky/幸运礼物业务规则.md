# 幸运礼物业务规则

## 1. 核心口径

| 术语 | 业务含义 | 数据口径 |
|---|---|---|
| 配置化幸运礼物 | 使用结构化概率规则和配置化轨道完成抽奖的幸运礼物 | `app_payer_gift_luck_lane.mechanism_type = 1` |
| 普通池 | 非新人用户使用的概率规则 | `app_payer_gift_luck_lane.lane_rule_id`，规则记录 `newcomer = 0` |
| 新人池 | 新人用户使用的独立概率规则 | `app_payer_gift_luck_lane.newcomer_lane_rule_id`，规则记录 `newcomer = 1` |
| 周奖池 | 按大区、UTC+3 自然周维护的奖励投放池 | Redis key：`payer:gift:luck:configured:pool:{region}:{periodStart}` |
| 基础抽奖轨道 | 按礼物与当前规则生成并消费的抽奖结果序列 | Redis List：`payer:gift:luck:configured:track:{giftId}:{ruleId}` |
| 内部倍数 | 抽奖倍数的整数存储精度 | x10；`5 = 0.5` 倍，`10 = 1` 倍，`2000 = 200` 倍 |
| 概率 | 单个结果的命中权重 | 万分之一；`5000 = 50%`，总和必须为 `10000` |
| 用户日 | UTC+3 的自然日 | 日期格式 `yyyyMMdd` |
| 自然周 | UTC+3、周一开始的自然周 | `periodStart` 为当周周一，格式 `yyyyMMdd` |
| 新用户 | 注册后未满 120 小时的用户 | `当前时间 - 注册时间 < 120h`；达到 120 小时转为非新用户 |
| 普通用户 | 统计窗口内幸运礼物总投入不超过分层阈值的用户 | 默认近 7 日投入 `<= 1,000,000` 金币 |
| 重度用户 | 统计窗口内幸运礼物总投入超过分层阈值的用户 | 默认近 7 日投入 `> 1,000,000` 金币 |
| 投产比 | 产出金币相对投入金币的比例 | `产出金币 / 投入金币 * 100%`；投入为 0 的口径待确认 |
| 高返时限 | 所有用户临时改用高返概率的每日时间段 | UTC+3 每日 `[19:00:00, 21:00:00)`，使用 98% 新用户概率 |
| 大倍率奖励 | 奖励投放池使用的高倍奖励 | 产品口径为中奖倍数 `>= 10`；与当前代码严格大于阈值的关系待确认 |

## 2. 配置、抽奖与运行态

### 2.1 基础配置与轨道

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|---|---|---|---|---|
| 配置启用门禁 | 发起幸运礼物抽奖 | `status = 0` 时本次结果直接为不中奖 | `status`：`1` 启用，`0` 停用 | `app_payer_gift_luck_lane`；配置状态独立于礼物主表上下架状态 |
| 机制选择 | 读取礼物幸运配置 | `mechanism_type = 1` 使用配置化机制；`0` 或空值按旧 `LANE` 机制处理 | `0 = LANE`，`1 = CONFIGURED`，空值兼容旧机制 | 所有幸运礼物抽奖入口 |
| 普通池选择 | 当前用户不满足新人条件 | 使用 `lane_rule_id` 指向的规则，且规则记录应满足 `newcomer = 0` | 规则必须有效：`status = 1` | 配置化幸运礼物 |
| 新人池选择 | 用户注册时长小于 120 小时且已配置新人规则 | 使用 `newcomer_lane_rule_id` 指向的规则，且规则记录应满足 `newcomer = 1` | 注册满 120 小时不再视为新人；未配置新人池时该字段为空 | 配置化幸运礼物；新人规则缺失时的回退策略待确认 |
| 无效规则处理 | 所选规则 `status = 0` | 将该规则按空规则处理 | `status`：`1` 有效，`0` 无效 | 普通池与新人池 |
| 概率归一 | 保存或校验配置化 `rule.items` | `sum(items[*].probability) = probabilityTotal` | `probabilityTotal = 10000` | 普通池与新人池的规则配置 |
| 倍数换算 | 读取规则或轨道中的中奖倍数 | `展示倍数 = multiple / 10` | x10 精度 | 概率规则、轨道元素、中奖结果 |
| 概率换算 | 读取规则中某个结果的概率 | `展示概率 = probability / 10000` | 万分之一精度；总和 `10000` | 概率展示与配置校验 |
| 规则价格快照 | 保存幸运礼物规则 | `rule.coin = app_payer_gift.coin`（保存时值） | 无 | `app_payer_gift_luck_lane_rule`；该字段是快照，不代表实时礼物价格 |
| 抽奖轨道隔离 | 为一次配置化抽奖定位轨道 | `key = prefix + giftId + ":" + selectedRuleId`；规则 ID 为空时仅保留 `giftId` | 普通池取 `lane_rule_id`；新人池取 `newcomer_lane_rule_id` | Redis 配置化轨道；不同礼物、不同规则使用不同轨道 |
| 轨道消费 | 执行配置化基础抽奖 | 从 List 左侧消费一个逻辑结果 | 正数为中奖倍数；`0`/`-1` 为一个未中奖坑位；`n < -1` 表示连续 `abs(n)` 个未中奖坑位 | `payer:gift:luck:configured:track:*` |
| 轨道概率核验 | 统计 Redis List 当前剩余倍率结构 | 正数元素各计 1 个逻辑坑位；负数元素按 `abs(n)` 计入 0 倍逻辑坑位；各倍率概率以逻辑坑位总数为分母 | `LLEN` 仅是物理元素数，不能直接作为概率分母 | 配置化抽奖轨道排查；剩余轨道结构不等于历史实际命中分布 |
| 空轨道重建 | 当前轨道 List 已空 | 按当前规则生成同构轨道，并写回同一 key 后继续使用 | 无 | 配置化基础抽奖轨道 |

### 2.2 用户统计与周奖池运行态

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|---|---|---|---|---|
| 用户日投入累计 | 每次配置化幸运礼物结算 | `inputAmount += 本次投入金币` | UTC+3 当日 | 用户日统计 Hash |
| 用户日返奖累计 | 每次配置化幸运礼物结算 | `rewardAmount += 本次返奖金币` | 未中奖时本次增加 `0` | 用户日统计 Hash |
| 用户日抽奖累计 | 每次配置化幸运礼物结算 | `drawTimes += 本次实际抽奖次数` | UTC+3 当日 | 用户日统计 Hash |
| 大倍率计数 | 当前代码判断 `rewardMultiple > configuredBigRewardMultiple` | `bigRewardCount += 1`，并记录 `lastBigRewardDraw = 当前日抽奖序号` | 产品定义为 `>= 10` 倍；代码比较符与配置值的映射待确认 | 用户日统计；用于每日次数和抽奖间隔限制 |
| 投放池命中记录 | 本次命中奖励投放池 | `lastPoolRewardDraw = 当前日抽奖序号` | 两次大倍率奖励至少间隔 50 次幸运礼物抽奖 | 用户日统计；当前字段是否足以表达 50 次间隔待确认 |
| 近 7 日投入累计 | 每次配置化幸运礼物结算 | `inputAmount += 本次投入金币` | 首次写入时 TTL 为 7 天 | 用户近 7 日统计；用于重度用户和投放候选判断 |
| 近 7 日返奖累计 | 每次配置化幸运礼物结算 | `rewardAmount += 本次返奖金币` | 首次写入时 TTL 为 7 天 | 用户近 7 日统计；用于 ROI 计算 |
| 近 7 日抽奖累计 | 每次配置化幸运礼物结算 | `drawTimes += 本次实际抽奖次数` | 首次写入时 TTL 为 7 天 | 用户近 7 日统计 |
| 用户投产比 | 判断用户收益表现 | `rewardAmount / inputAmount * 100%` | 拉升目标默认 `95%`；投放低投产阈值默认 `60%`；投入为 0 的处理待确认 | 用户分层后的拉升与奖励投放候选判断；统计范围见具体规则 |
| 周奖池初始化维度 | 创建或定位当前周奖池 | 按 `region + periodStart` 唯一定位 | UTC+3 周一；大区取 `UserRegionType` 的 int 值 | 配置化周奖池 |
| 周奖池投放预扣 | 奖励投放池命中且预扣成功 | `releasedAmount += 本次额外投放金币`；投放后 `releasedAmount <= totalAmount` | 本次奖励不得超过 `totalAmount - releasedAmount` | Redis 周奖池 Hash；原子性与失败回滚待确认 |
| 周奖池盈利累计 | 幸运礼物结算 | `profitAmount += 本次投入金币 - 本次返奖金币` | 可正可负的边界处理待确认 | 当前大区、当前自然周；用于下周奖池初始化 |
| 周奖池异步回刷 | 定时任务同步运行态奖池数据 | 将 Redis `releasedAmount` 异步回写数据库 `released_amount` | 调度频率与一致性容忍度待确认 | Redis 为实时运行态，数据库为异步记录 |
| 周奖池过期 | 当前 UTC+3 自然周结束 | key 保留到本周结束后再多 1 天 | 具体过期时刻待确认 | 周奖池 Redis Hash |
| 用户日统计过期 | UTC+3 当日结束 | key 到期删除 | 当日结束时刻 | 用户日统计 Redis Hash |

### 2.3 用户策略与结算

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|---|---|---|---|---|
| 有效倍率集合 | 后台配置幸运礼物概率 | 只允许从有效倍率集合选择 | `0、0.1、0.2、0.5、1、2、3、5、7、10、15、20、30、50、70、100、150、200`；`300` 倍废弃 | 普通池和新人池概率配置 |
| 返奖金币计算 | 单个抽奖结果倍数大于 0 | `返奖金币 = 本次礼物单价 * 中奖倍数` | `0` 倍返奖为 `0`；小数结果的取整规则待确认 | 客户端到账、用户统计和报表产出 |
| 独立轨道周期 | 为某礼物及所选规则生成基础轨道 | 每周期共 10000 个逻辑坑位，各倍率坑位数与生效概率一致 | 周期长度 `10000` | 不同礼物不共用轨道；同一礼物的普通与新人规则由不同 `ruleId` 隔离 |
| 高返时限路由 | UTC+3 每日 19:00:00 至 20:59:59 发起抽奖 | 所有用户统一使用投产比 98% 的新人概率 | `[19:00:00, 21:00:00)`；客户端时区不参与判断 | 所有配置化幸运礼物，包括非新用户 |
| 高返结束回落 | 抽奖时间达到 UTC+3 21:00:00 | 恢复该礼物常规概率规则 | 每日重新生效 | 所有配置化幸运礼物 |
| 普通用户分层 | 统计窗口内全部幸运礼物投入不超过阈值 | `sum(近 N 日幸运礼物投入) <= 分层阈值` | 默认 `N = 7` 日、阈值 `1,000,000` 金币；均可配置 | 用户分层；各幸运礼物投入合并计算 |
| 重度用户分层 | 统计窗口内全部幸运礼物投入超过阈值 | `sum(近 N 日幸运礼物投入) > 分层阈值` | 默认 `N = 7` 日、阈值 `1,000,000` 金币；均可配置 | 用户分层；各幸运礼物投入合并计算 |
| 重度用户拉升触发 | 重度用户在当前幸运礼物的投产比低于目标 | `当前礼物投产比 = 当前礼物产出 / 当前礼物投入` | 默认目标 `95%`；达到或超过目标时停止拉升 | 每个用户、每个幸运礼物分别判断 |
| 拉升差值换算 | 重度用户需要拉升且执行本次奖励计算 | `投产差值 = 投入 - 产出`；`单价倍值 = 投产差值 / 礼物单价` | 从单价倍值接近的上级有效倍率之下至少一级的倍率中随机奖励 | 重度用户当前幸运礼物 |
| 拉升间隔 | 上一次抽奖已产出投产比拉升结果 | 下一次抽奖不得再次产出拉升结果 | 两次拉升结果之间至少有 1 次非拉升抽奖 | 重度用户拉升 |
| 投放候选 | 用户为重度用户，或用户投产比不高于低投产阈值 | 满足任一条件即可进入随机投放候选范围 | 低投产阈值默认 `60%`，可配置；投产比统计范围待确认 | 奖励投放池 |
| 投放奖励下限 | 从奖励投放池向候选用户发放大倍率奖励 | 中奖倍数应不低于大倍率下限 | 产品默认 `>= 10` 倍 | 奖励投放池；当前代码的严格大于比较仍需确认 |
| 每日大倍率上限 | 同一用户在当前 UTC+3 自然日已获得大倍率奖励 | 第 1 至第 3 个允许；尝试第 4 个时替换为小倍率 | 每日最多 `3` 个 | 奖励投放池；并发下不得突破 |
| 大倍率抽奖间隔 | 同一用户距上次大倍率奖励的抽奖次数不足 50 | 强制将本次大倍率替换为小于 10 倍的结果，并仅按替换结果结算 | 间隔 `< 50` 时替换，`>= 50` 时允许 | 奖励投放池；并发下不得突破 |
| 配置变更生效 | 管理员保存新的概率配置 | 保存后的新抽奖使用新规则，已完成抽奖和历史报表保持原结果 | 新旧规则切换必须避免继续消费旧概率轨道 | 幸运礼物概率编辑；通过新 `ruleId` 或失效旧轨道实现 |
| 抽奖幂等 | 送礼请求超时、重试或 Combo 快速点击 | 每个有效赠送事件只扣款一次并生成一次抽奖结果 | 重复请求不得重复结算 | 送礼、Combo、返奖及报表链路 |

## 3. 客户端展示与广播

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|---|---|---|---|---|
| Combo 计数 | 用户连续执行幸运礼物 Combo | 赠送次数和礼物数量按每次有效点击的实际赠送量累计 | 新一轮 Combo 不继承上一轮累计 | 幸运礼物专属 Combo |
| 流光数量封顶 | 当前 Combo 展示累计数量达到或超过 999 | `展示数量 = min(实际累计数量, 999)` | 展示上限 `x999`；后台按实际数量统计 | 侧边通知流光 |
| 一级中奖播报 | 单次中奖倍数落入一级区间 | 展示本次中奖金币与倍数，仅中奖者可见 | 默认 `[5, 20)` 倍；边界可配置 | 房间内分级中奖播报 |
| 二级中奖播报 | 单次中奖倍数落入二级区间 | 展示本次中奖金币与倍数，仅中奖者可见 | 默认 `[20, 100)` 倍；边界可配置 | 房间内分级中奖播报 |
| 三级中奖播报 | 单次中奖倍数达到三级下限 | 全房间展示、设备震动、边框特效；展示层级最高 | 默认 `>= 100` 倍；边界可配置 | 中奖者当前所在房间 |
| 播报合并窗口 | 同一用户在当前播报开始后继续 Combo 并命中可合并等级 | 合并窗口内累加倍数与金币；不满足当前合并范围的结果进入队列 | 窗口 `1.3s`；单个动画 `2.5s` | 一级合并 `[5, 20)` 倍，二级合并 `[5, 100)` 倍，三级合并 `>= 5` 倍 |
| 房间中奖广播聚合 | 一笔赠送包含多个达到广播阈值的倍率奖励 | `广播倍数 = sum(达到广播阈值的中奖倍数)` | 低于阈值的结果不计入；聚合数量上限暂定 5 个 | 可跳转至中奖用户当前房间的广播 |
| 基础播报可见性 | 用户送出幸运礼物 | 展示本轮赠送总数与抽奖返币总数 | 仅送礼者本人可见；0 倍时横幅仍展示但不展示 0 金币返币标识 | 幸运礼物基础播报 |

## 4. 后台配置与周奖池

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|---|---|---|---|---|
| 礼物客户端可见 | 幸运礼物已配置有效概率且礼物处于上架状态 | 两个条件同时满足才展示 | 缺少概率或处于下架状态均不展示 | 客户端礼物面板 |
| 奖池维度开放范围 | 管理员添加幸运礼物配置 | 可选独立奖池和新人奖池 | 共享奖池、区域奖池暂不启用 | 幸运礼物配置后台 |
| 概率保存校验 | 管理员新增或编辑概率配置 | 展示概率之和必须等于 1；内部值之和必须等于 10000 | 必填礼物、倍率和概率 | 幸运礼物配置后台 |
| 周奖池周期生成 | 每个自然周周一 00:00:00 | 为新自然周生成唯一一组奖池数据 | 重复执行不得生成重复周期；使用时区待确认 | 幸运礼物投放奖池后台 |
| 周奖池默认金额 | 生成新自然周奖池 | `totalAmount = 上周幸运礼物总盈利 * 奖池比例` | 默认比例 `10%`，可配置 | 新生成周期；大区或全局聚合范围待确认 |
| 周奖池剩余金额 | 查询或编辑当前周期奖池 | `remainingAmount = totalAmount - releasedAmount` | 结果不得为负 | 投放奖池列表与奖励预扣 |
| 周奖池编辑下限 | 管理员调整当前周期奖池金额 | `newTotalAmount > releasedAmount` | 等于或小于已投放金额时拒绝 | 投放奖池编辑 |
| 周奖池编辑上限 | 管理员调整当前周期奖池金额 | `newTotalAmount + releasedAmount < previousWeekProfit` | 等于或超过上周总盈利时拒绝 | 投放奖池编辑；并发保存使用最新 `releasedAmount` |

## 5. 报表规则

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|---|---|---|---|---|
| 总盈利 | 汇总筛选范围内幸运礼物数据 | `总盈利 = 总投入 - 总产出` | 无 | 幸运礼物报表（礼物）整体看板 |
| 总投产比 | 汇总筛选范围内幸运礼物数据 | `总投产比 = 总产出 / 总投入 * 100%` | 总投入为 0 时的展示待确认 | 幸运礼物报表（礼物）整体看板 |
| 总参与人数 | 汇总筛选范围内幸运礼物数据 | 按送礼用户去重计数 | 同一用户多次赠送只计 1 人 | 幸运礼物报表（礼物）整体看板 |
| 礼物日报粒度 | 生成幸运礼物每日统计 | 每个礼物、每个统计日一条记录；无赠送时数值展示 0 | 默认查询最近 7 天 | 幸运礼物报表（礼物） |
| 礼物日报投入产出 | 生成单日统计 | `投入 = sum(礼物单价 * 赠送数量)`；`产出 = sum(实际返奖金币)`；`单日投产比 = 产出 / 投入 * 100%` | 投入为 0 时的展示待确认 | 幸运礼物报表（礼物） |
| 礼物累计投产比 | 生成截止统计日的累计值 | `累计投产比 = 上线日至统计日累计产出 / 累计投入 * 100%` | 已结束统计日的累计值后续不变 | 幸运礼物报表（礼物） |
| 用户报表粒度 | 一笔赠送涉及一个或多个收礼用户 | 每个收礼用户、每次赠送事件单独一条记录 | Combo 每次点击按实际事件拆分 | 幸运礼物报表（用户） |
| 用户报表投入产出 | 生成用户明细 | `投入 = 赠送时礼物单价 * 赠送数量`；`投产比 = 本条产出 / 本条投入 * 100%` | 使用赠送时价格和用户信息快照 | 幸运礼物报表（用户） |
| 历史快照 | 礼物价格或概率配置变更 | 新事件使用新配置，历史投入、产出和中奖记录保持不变 | 无 | 礼物报表、用户报表及抽奖明细 |

## 6. 数据模型与约束

用户筛选、金币余额、审核状态、安全等级及 `user:info:{user_id}` 缓存映射详见 `数据库表结构.md`。

### 6.1 配置主表 `app_payer_gift_luck_lane`

- 一条记录对应一个礼物当前使用的幸运抽奖配置，`gift_id` 为主键并关联 `app_payer_gift.id`。
- 普通规则由 `lane_rule_id` 引用；新人规则由可空的 `newcomer_lane_rule_id` 引用。
- 配置化机制以规则表和 Redis key 的 `region:int` 管理周奖池，不使用旧字段 `region` 作为当前周奖池口径。
- `lane_key`、`lane_type`、`region` 属于旧轨道兼容字段，不是配置化机制的核心校验字段。
- 首次保存生成 `create_time`；修改概率或启停状态后更新 `update_time`。

### 6.2 规则表 `app_payer_gift_luck_lane_rule`

- 普通池和新人池共用该表，以 `newcomer` 区分。
- `gift_id` 必须与配置主表的 `gift_id` 一致。
- `rule` 为结构化 JSON，必须包含 `items` 和 `probabilityTotal`。
- 普通规则名称通常为礼物名，新人规则名称通常带 `newcomer` 后缀；“通常”不是强制唯一性约束。
- `remark` 当前保存逻辑写入礼物名。

规则结构：

```json
{
  "items": [
    { "multiple": 0, "probability": 5000 },
    { "multiple": 10, "probability": 5000 }
  ],
  "probabilityTotal": 10000
}
```

### 6.3 奖池表 `app_payer_gift_luck_configured_pool`

当前已知信息仅确认该表为奖池表，字段、主键、状态枚举、周期字段及与 Redis 的完整映射尚未确认。使用前必须先查表结构并补充规则。

### 6.4 抽奖明细表 `app_payer_luck_gift_report_detail`

- 每条记录按一次幸运礼物赠送事件聚合，包含 `sender_user_id`、`recipient_user_id`、`gift_id`、`gift_count`、`raffle_count`、`input_coin`、`output_coin`、`pool_release_coin`、`room_id`、`create_time`。
- `input_coin` 为该事件总投入，当前核验满足 `input_coin = gift_count * 礼物单价`；`output_coin` 为该事件全部抽奖结果的总返奖。
- 当前测试数据中，`raffle_count` 表现为正倍率中奖次数：`gift_count - raffle_count` 可统计 0 倍次数；该字段名称与精确定义仍需代码或开发说明最终确认。
- 表内不保存逐次抽奖的 `multiple` 或结果数组。当 `gift_count > 1` 时，只能得到事件总返奖与正倍率中奖总数，不能据此唯一反推出各倍率的实际命中次数。
- 落库时点、主键幂等约束及周奖池额外投放在 `output_coin` / `pool_release_coin` 中的精确关系仍待确认。

## 7. Redis 运行态

| 用途 | Key | 类型 | 生命周期 |
|---|---|---|---|
| 大区周奖池 | `payer:gift:luck:configured:pool:{region}:{periodStart}` | Hash | 当前周结束后再保留 1 天 |
| 用户日统计 | `payer:gift:luck:configured:user:day:{userId}:{yyyyMMdd}` | Hash | 到 UTC+3 当日结束 |
| 用户近 7 日统计 | `payer:gift:luck:configured:user:recent7d:{userId}` | Hash | 首次写入时设置 7 天 |
| 配置化抽奖轨道 | `payer:gift:luck:configured:track:{giftId}:{ruleId}` | List | TTL 尚未确认；消费完后按当前规则重建 |

关键字段：

| Key 类别 | 字段 | 含义 |
|---|---|---|
| 周奖池 | `totalAmount` | 本周期奖池总额 |
| 周奖池 | `releasedAmount` | 本周期已通过周奖池额外投放的金币 |
| 周奖池 | `profitAmount` | 本周期大区幸运礼物真实盈利金币 |
| 用户日 | `inputAmount` / `rewardAmount` / `drawTimes` | 当日投入、返奖与实际抽奖次数 |
| 用户日 | `bigRewardCount` / `lastBigRewardDraw` | 当日大倍率次数与最近一次大倍率中奖序号 |
| 用户日 | `lastPoolRewardDraw` | 最近一次投放池命中的当日抽奖序号 |
| 近 7 日 | `inputAmount` / `rewardAmount` / `drawTimes` | 近 7 日投入、返奖与抽奖次数 |

用户日 Hash 仅保存 UTC+3 当日累计值，不保存事件时间或按时段拆分的数据；核对高返、非高返等日内窗口时，以带 `create_time` 的数据库明细拆分，Redis 仅用于校验当日实时总量及报表异步差额。

## 8. 标准排查链路

1. 查询 `app_payer_gift_luck_lane`，确认 `gift_id`、`status`、`mechanism_type`、普通规则 ID 与新人规则 ID。
2. 查询 `app_payer_gift_luck_lane_rule`，确认规则归属、`newcomer`、`status`、倍数精度及概率总和。
3. 记录抽奖服务端时间并换算 UTC+3，先判断是否处于 `[19:00:00, 21:00:00)` 高返时限。
4. 非高返时限按注册时长判断新人身份；高返时限统一路由新人概率。确认最终所选 `ruleId`。
5. 使用所选规则 ID 定位 `payer:gift:luck:configured:track:{giftId}:{ruleId}`，检查 10000 坑位周期、轨道生成与消费。
6. 核对近 7 日全部幸运礼物投入以确认普通/重度分层，再按当前礼物投入产出判断是否执行 95% 拉升。
7. 结算后核对用户日统计及近 7 日统计的投入、返奖、抽奖次数；证明近 7 日数据符合滚动窗口。
8. 涉及大倍率时同时核对 10 倍边界、每日最多 3 个、至少间隔 50 次以及并发保护。
9. 涉及奖励投放池时核对用户资格、`lastPoolRewardDraw`、原子预扣及周奖池 `releasedAmount`、剩余金额。
10. 核对报表时按赠送事件追溯价格快照、投入、实际返奖、用户明细，再汇总礼物日报和整体看板。
11. 核对数据库奖池回刷或抽奖明细时，先补齐对应表结构与异步时序口径。

## 9. 数据质量门禁

- 概率项为空、`probabilityTotal != 10000`、概率项求和不等于 `10000` 时，规则不得视为有效配置。
- 主表引用规则不存在、规则 `gift_id` 不一致、普通/新人标记不匹配时，必须作为配置异常报告。
- Redis 数值字段缺失、非整数或出现不符合业务约束的负值时，必须单独输出“异常声明”。
- `releasedAmount` 的 Redis 与数据库差异须结合异步回刷周期判断；在周期口径确认前不得直接定性为数据错误。
- 近 7 日统计若仅表现为单个固定 TTL Hash，必须先证明其数据窗口与“当前时刻向前 7 日”一致，否则作为实现异常报告。
- 概率编辑后若仍消费旧规则轨道，必须作为配置生效异常报告。
- 高返窗口内报表投产比持续接近普通规则，且高返规则轨道消费量显著小于该窗口抽奖量时，应优先排查高返路由或时间配置是否实际生效，不得直接归因于概率随机波动。
- 业务允许的倍率必须同时满足有效倍率集合和 x10 内部精度；不符合精度的边界值不能作为真实倍率入库。
- 查询数据库时先执行 `SHOW COLUMNS FROM <表名>`；发现新字段、枚举或关系后更新本文。
