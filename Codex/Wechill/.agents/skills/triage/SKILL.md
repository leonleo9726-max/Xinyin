# Triage

通过一个小型 triage roles 状态机，推进项目 issue tracker 上的 issues。

开始读取或修改 issue 前，确认 tracker 和 label mapping 已配置。配置缺失时，只根据用户提供的材料给出分类建议与待补信息，不查询或写入外部 tracker。

triage 期间发布到 issue tracker 的每条 comment 或 issue **必须**以下列 disclaimer 开头：

```
> *This was generated by AI during triage.*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 如何编写耐用的 agent briefs
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/` knowledge base 如何工作

## Roles

两个 **category** roles：

- `bug` — 某些东西坏了
- `enhancement` — 新功能或改进

五个 **state** roles：

- `needs-triage` — maintainer 需要评估
- `needs-info` — 等待 reporter 提供更多信息
- `ready-for-agent` — 已完整说明，可交给 AFK agent
- `ready-for-human` — 需要人工实现
- `wontfix` — 不会处理

每个已 triaged issue 应恰好带一个 category role 和一个 state role。如 state roles 冲突，先标出并询问 maintainer，再做其他操作。

这些是 canonical role names；issue tracker 中实际 label strings 可能不同。映射应已提供；如未提供，先使用 `$setup-matt-pocock-skills`。

State transitions：unlabeled issue 通常先进入 `needs-triage`；然后转到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。reporter 回复后，`needs-info` 回到 `needs-triage`。maintainer 可随时 override；遇到异常 transitions，先标出并询问再继续。

## 调用

maintainer 调用 `$triage` 并用自然语言描述需求。解释请求并执行。示例：

- "Show me anything that needs my attention"
- "Let's look at #42"
- "Move #42 to ready-for-agent"
- "What's ready for agents to pick up?"

## 展示需要关注的内容

查询 issue tracker，并按 oldest first 展示三个 buckets：

1. **Unlabeled** — 从未 triaged。
2. **`needs-triage`** — 评估中。
3. **自上次 triage notes 后 reporter 有活动的 `needs-info`** — 需要重新评估。

展示 counts 和每个 issue 的一行 summary。让 maintainer 选择。

## Triage 指定 issue

1. **Gather context.** 读取完整 issue（body、comments、labels、reporter、dates）。解析此前 triage notes，避免重复询问已解决问题。使用项目 domain glossary 探索代码库，并尊重相关 ADRs。读取 `.out-of-scope/*.md`，并指出与当前 issue 相似的历史拒绝。

2. **Recommend.** 向 maintainer 给出 category 和 state 推荐、理由，以及与 issue 相关的简短代码库 summary。等待指示。

3. **Reproduce (bugs only).** 在 grilling 前尝试复现：读取 reporter steps、追踪相关代码、运行 tests 或 commands。报告结果：成功复现及 code path、复现失败、或信息不足（强 `needs-info` 信号）。确认复现会显著增强 agent brief。

4. **Grill (if needed).** 如果 issue 需要补充细节，运行 `$grill-with-docs` session。

5. **Apply the outcome:**
   - `ready-for-agent` — 发布 agent brief comment（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human` — 使用 agent brief 同样结构，但说明为何不能委托（judgment calls、external access、design decisions、manual testing）。
   - `needs-info` — 发布 triage notes（模板如下）。
   - `wontfix` (bug) — 礼貌说明后关闭。
   - `wontfix` (enhancement) — 写入 `.out-of-scope/`，在 comment 中链接，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage` — 应用该 role。如有部分进展，可选择评论。

## 快速 state override

如果 maintainer 说 "move #42 to ready-for-agent"，信任并直接应用该 role。确认即将执行的动作（role changes、comment、close），然后执行。跳过 grilling。如果未经过 grilling session 就移动到 `ready-for-agent`，询问是否需要写 agent brief。

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

把 grilling 中已解决的内容全部记录到 "established so far"，避免工作丢失。问题必须具体且可执行，不能只是 "please provide more info"。

## 恢复之前会话

如果 issue 上已有 triage notes，先读取它们，检查 reporter 是否回答了未决问题，并在继续前展示更新后的情况。不要重复询问已解决问题。
