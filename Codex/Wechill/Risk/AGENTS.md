# AGENTS.md — Risk 风控系统

> 继承父目录 `..\\AGENTS.md` 的项目边界、环境、数据库、数据质量与输出规范。本文件只补充 Risk 业务约束；冲突时以父目录或用户明确指令为准。

## 1. 范围与规则来源

- `Risk/` 管理设备充值限制、设备/IP 注册限制、主播设备登录、三方充值身份校验、IP 白名单及账号/设备/IP 封禁处置。
- 处理查询、判断、实现或处置前，必须完整读取 `核心业务规则.md`。

## 2. 领域与数据

### 2.1 不可混用的计数域

| 计数域 | 口径 | 关键限制 |
|---|---|---|
| 设备注册 | 同一稳定设备下的有效注册账号数 | 每设备最多 2 个。 |
| 设备充值 | 同设备 Google、Apple 首次支付成功订单金额 | 三方/H5 不计入；退款、拒付、补单不改变累计。 |
| 主播设备占用 | 同设备的主播类账号（已加入公会账号或公会长） | 每设备最多 1 个；普通账号不占用。 |
| IP 注册 | 同一注册 IP 下的有效账号数 | 每 IP 最多 5 个；有效 IP 白名单可豁免。 |
| 白名单登录数 | 白名单 IP 历史成功登录的去重 `user_id` | 默认上限 8，可配置为正整数，不按自然日重置。 |

### 2.2 核心表

| 表名 | 领域职责 | 约束 |
|---|---|---|
| `app_user_device` | 设备与账号关联，支撑设备注册、主播占用与存量关系 | 不假定其存储订单或完整登录流水。 |
| `app_user_ban` | 账号、设备及组合封禁记录 | 封禁历史只追加，不覆盖。 |
| `app_user_ban_ip` | IP 封禁记录 | IP 解封不自动解除账号或设备限制。 |
| `app_user_ip_whitelist` | IP 白名单、有效期和登录上限配置 | 仅按声明范围豁免限制。 |

## 3. 查询与处置约束

1. 用户输入数字默认按 `app_user.user_number` 查询；仅当用户明确指定为 `user_id` 时，才直接按 `user_id` 查询。
2. 首次查询任一风险表，先执行 `SHOW COLUMNS FROM <table>`；读取结果必须展示列名和前 3 行。字段、枚举、关联键不得猜测。
3. 设备充值从订单来源按设备聚合；登录 IP 与白名单历史登录数从登录日志来源聚合。当前四张表不自动构成完整订单或登录流水。
4. 当前状态取最新有效限制或封禁记录；账号不存在时，还需检查可用的扩展/审核用户来源后才能下结论。
5. 发现字段映射、枚举或表关系后，立即维护 `数据库表结构.md`；文件不存在时，基于已查 Schema 创建，禁止预填未知字段。
6. 封禁、解封、白名单变更、充值限制调整和删除账号属于外部状态变更，只有用户明确要求时才可写入。批量写入前必须预览影响对象和数量。
7. 封禁需具备时长、理由、证据和不超过 100 字的备注；白名单需记录原因与有效期；删除账号前须检查未结算收益、未完成提现和进行中申诉。
8. 解封仅解除指定对象的本次限制，不得隐式解除账号、设备、IP、设备充值、收益或提现的其他限制。所有处置、调整和白名单变更必须保留审计日志。

## 4. 场景底线

- **设备充值**：支付前按设备重新聚合；`limit_type` 为 `0` 不限、`1` 200 USD、`2` 1000 USD、`3` 全面限制，其他/无配置按 500 USD。仅充值账号/设备白名单可跳过充值限制，累计仍需记录。
- **注册、登录与入会**：注册先检查设备再检查 IP；主播类登录、入会申请、接受邀请和发送邀请都必须由服务端校验设备主播占用。受限申请不写公会关系，受限邀请不创建记录且不泄露关联账号信息。
- **三方充值**：须先完成 `Wechill ID`、一次性验证码、充值会话和有效期的服务端绑定校验。验证码当前为 4 位、提示有效期 120 秒、一次性使用；支付授权必须一次性且接口幂等，验证码不得写入 URL、前端日志或本地明文存储。
- **存量数据**：超限历史关系不自动删除；历史多主播设备以功能上线后首次成功登录的主播类账号作为占用者。

## 5. 输出要求

- 使用简体中文，结论先行；数据对比和判定链路使用 Markdown 表格。
- 对每个风险结论明确对象、依据、当前状态、影响范围和是否需要人工确认。
- 数据异常在结论前以 **异常声明** 单列；规则或字段不明时以 **待确认** 单列。
