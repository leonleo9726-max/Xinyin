# Risk 核心业务规则

> 依据 `风控系统需求文档.md` v1.7 与 `风控系统需求文档-测试用例.md` 提炼。需求文档为规则来源；测试用例用于校验边界。未明确的口径集中列于文末，不能自行实现为默认行为。

## 1. 基础定义

| 名称 | 定义 |
|---|---|
| 设备 | 服务端稳定设备标识（如 `risk_device_hash` / `device_id`）。卸载、重装或清理客户端缓存不得改变其关联关系。 |
| 有效注册账号 | 已成功注册且未被后台删除的账号；仅封禁但未删除的账号仍保留为风控证据。 |
| 主播类账号 | 已加入公会的账号，以及公会长；未加入公会的普通账号不属于主播类。 |
| 官方充值 | Google、Apple 的首次支付成功订单，金额沿用美元口径。 |
| 历史登录账号数 | 某 IP 历史成功登录过的去重 `user_id` 数量；不按自然日重置。 |
| 最新有效记录 | 当前状态判断取最近一条仍有效的封禁或限制记录；历史记录只追加，不覆盖。 |

## 2. 数据归属

| 数据表 | 领域职责 | 支撑的核心规则 | 字段与关联待确认 |
|---|---|---|---|
| `app_user_ban` | 账号、设备及组合封禁的处置记录与当前状态来源 | 封禁处置、账号解封、设备封禁、历史封禁记录 | 封禁对象类型、对象标识、时长、有效状态、证据、操作人、解封信息及审计关联。 |
| `app_user_ban_ip` | IP 封禁的独立记录与当前状态来源 | IP 封禁、IP 解封、IP 封禁历史 | IP、关联账号/设备、时长、有效状态、证据、操作人、解封信息及审计关联。 |
| `app_user_ip_whitelist` | IP 白名单、有效期与白名单登录上限配置 | IP 注册豁免、白名单 IP 登录总数限制 | IP、有效期、历史登录账号上限、添加/移除原因、操作人与操作日志关联。 |
| `app_user_device` | 服务端稳定设备与账号的关联关系 | 设备注册上限、主播设备占用、设备充值聚合、存量兼容 | 设备标识、账号标识、注册/登录关系、主播占用状态、删除状态及创建/更新时间。 |

> `app_user_device` 只承载设备-账号关联，不应默认推定其存储充值订单或登录流水；设备充值累计和 IP 历史登录账号数仍需从对应订单、登录日志来源按业务口径聚合。

## 3. 核心规则

| Rule Name | Trigger Condition | Formula | Threshold Values | Applicable Policy |
|---|---|---|---|---|
| 设备充值累计 | 官方充值订单首次支付成功 | `device_recharge = SUM(Google + Apple 首次成功订单金额)`，按设备聚合 | 仅 Google、Apple；美元 | 退款、拒付不扣减；补单不新增或回补。三方/H5 充值不计入本期累计。充值准备或下单前必须重新查询。 |
| 设备充值限制 | 用户发起充值 | `amount + device_recharge > limit` 时拦截 | `limit_type=0`：不限；`1`：200 USD；`2`：1000 USD；`3`：直接拦截；其他/无配置：500 USD 全局默认 | 限制命中后作用于该设备全部账号。充值账号白名单或充值设备白名单可跳过该限制，但仍记录设备累计；IP 白名单、设备注册白名单不影响本规则。 |
| 三方充值身份校验 | 访问三方充值链接、发送或提交验证码 | 校验 `Wechill ID + 一次性验证码 + 充值会话 + 有效期` 的绑定关系 | 当前验证码为 4 位数字；提示有效期 120 秒，以服务端为准 | 无效、封禁、注销或不可用账号不得发送验证码或进入支付。验证码单次使用，成功即失效；发送须限单 ID、单设备、单 IP 频率；错误达到阈值后短时锁定。仅校验通过后签发一次性支付授权，接口必须幂等。 |
| 单设备注册上限 | 注册前校验 | `count(valid_accounts by device) < 2` 才允许注册 | 每设备最多 2 个有效注册账号 | 设备标识缺失或异常时禁止注册或转人工校验。后台软删除账号后，设备与 IP 注册计数同步减少并释放名额。 |
| 单设备主播登录 | 主播类账号登录前校验 | 同一设备仅允许一个主播类账号占用 | 每设备最多 1 个主播或公会长 | 普通账号可登录，不占用主播名额。相同已占用主播可继续登录；无占用时首次成功登录的主播类账号写入占用；有其他主播类账号占用时拒绝登录。 |
| 加入公会防绕过 | 主动申请、接受邀请或公会长发送邀请前 | 校验目标设备是否已被其他主播类账号占用 | 每设备最多 1 个主播类账号 | 用户申请/接受邀请受限时，不写入公会关系且不占用主播名额；公会长邀请受限时不创建邀请记录，且不得暴露设备关联或其他账号信息。所有入口以服务端结果为准。 |
| 单 IP 注册上限 | 注册前校验 | `count(valid_accounts by registration_ip) < 5` 才允许注册 | 每 IP 最多 5 个账号 | 不按身份筛选，仅按数量统计。公共网络可能误伤，应结合设备规则处置。命中有效 IP 白名单时，豁免本规则。 |
| IP 白名单 | 白名单 IP 注册或首次登录 | 注册：跳过 IP 注册上限；登录：`count(distinct successful_login_user_id) < configured_limit` 才允许新账号首次登录 | 历史登录账号上限默认 8，可配置正整数；有效期为 7 天、30 天或永久 | 仅豁免 IP 注册数量限制，不豁免设备注册、主播设备登录、设备充值、收益/提现或 IP 封禁。达到登录上限后，已计入账号可继续登录，新账号首次登录受限。永久白名单需二次审批。 |
| 封禁处置 | 人工或系统命中风险后 | 根据封禁类型分别作用于账号、设备、IP | 时长：1h、6h、12h、1 天、2 天、3 天、7 天、永久 | 封 IP 仅影响目标 IP；“封号封设备封 IP-慎用”同时封禁设备全部账号、当前设备和目标账号最近登录 IP。封禁时间、理由、证据、备注均必填；备注最多 100 字；成功后写封禁记录和审计日志。 |
| 解封独立性 | 账号、设备充值或 IP 解封 | 仅解除本次指定对象的指定限制 | 无 | 账号解封不自动解除设备、IP、设备充值、收益或提现限制；IP 解封不自动解除账号/设备封禁，也不自动加入白名单；设备充值解封只恢复充值能力。解封原因可为空，操作必须留痕。 |
| 删除账号与审计 | 后台删除关联账号 | 软删除账号，并同步减少设备/IP 有效注册计数 | 删除原因必填 | 有未结算收益、未完成提现或进行中申诉时禁止删除。删除不清除设备、IP、充值、公会和审计证据；审计归档永久保留。 |
| 存量数据兼容 | 新规则上线后遇到历史超限设备/IP | 注册、登录、充值均按新阈值重新判断 | 设备注册 2、主播登录 1、IP 注册 5；充值按设备聚合 | 不自动删除或批量清退历史关联。历史多主播设备以功能上线后首次成功登录的主播类账号作为占用者；历史 Google/Apple 充值重新按设备聚合，且不清零。 |

## 4. 执行优先级与隔离原则

1. 先校验账号、设备和 IP 的当前可用状态，再执行注册、登录、入会或支付动作；所有关键判断均由服务端完成。
2. 充值统计、设备注册、主播登录、IP 注册是独立计数域：不得相互替代或因一项白名单而默认豁免其他规则。
3. 白名单仅按其声明范围生效：充值账号/设备白名单只影响充值限制；IP 白名单只豁免 IP 注册上限。
4. 解除限制也必须按对象和限制类型独立执行，禁止以账号解封、IP 解封或充值解封隐式解除其他限制。
5. 注册、入会、验证码校验、封禁、解封、删除等写操作必须幂等，避免重复请求产生额外关系、支付会话或处置记录。
6. 所有自动触发、人工调整、白名单变更、封禁、解封和删除操作必须记录操作人、原因、时间和审计日志；系统操作人使用 `system`。

| 事项 | 当前明确状态 |
|---|---|
